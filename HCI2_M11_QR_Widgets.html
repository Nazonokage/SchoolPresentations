Topic 1 · Widgets
What Is a Widget?
A widget is an application or specific UI component embedded into a webpage that lets the user perform a function or access a service without leaving the current page.
🧩 General Widget
Any embedded application or component on a webpage — it has a defined purpose, occupies a section of the page, and works independently of the rest of the site.

Examples: weather forecast panel, live chat bubble, embedded map, social share buttons.
⚡ JavaScript Widget
A JavaScript widget is specifically a block of embedded JavaScript code that adds dynamic interactivity to otherwise static HTML pages.

Once you “drop” a JavaScript widget onto your page, you simply configure its settings to control how it behaves.

Topic 2 · Adding JavaScript
Inline vs External Scripts
Two main ways to get JavaScript into your HTML file.
✏️ Method 1 — Inline (Direct)
Type your JavaScript code directly inside a <script> tag within the HTML file.
html
<script>
  var str = "Hello World!";
</script>
💡 Pro Tip: When writing JS directly into HTML, you do not add <script> tags inside the JavaScript code itself — the browser already knows it's a script block.
📂 Method 2 — External File
For larger or reusable scripts, link to a separate .js file using the src attribute.
html
<!-- Your own file -->
<script src="scripts/main.js"></script>

<!-- Third-party CDN library -->
<script src="https://cdnjs.cloudflare.com/..."></script>
💡 When to Use Each
Inline: Quick snippets, small page-specific logic
External: Reusable code, third-party libraries, production projects
Topic 2 · Script Placement
Where to Put Your <script> Tag
The location of your <script> tag dictates when it executes. Choose based on your needs.
LocationExecution TimingBest Use Case
In <head> Executes immediately as the page loads Small scripts required for initial setup — but can slow rendering
Where widget is dropped Executes when that specific element loads Widgets that need to bind to an element immediately
Before </body> ✅ Executes at the very end of the loading process Recommended. Full HTML is parsed before JS runs — safe for DOM manipulation and heavy widgets
html — recommended pattern
<!DOCTYPE html>
<html>
<head>
  <!-- CDN libraries loaded here -->
  <script src="https://cdn.../library.js"></script>
</head>
<body>

  <!-- All your HTML content here -->

  <!-- Your JS goes LAST, before closing body -->
  <script>
    // DOM is fully loaded, safe to use!
    document.getElementById("myEl");
  </script>
</body>
</html>
⚠️ Why NOT always in <head>?
If your script runs in the <head> and tries to select a DOM element that hasn't been created yet — it will return null and likely crash.

This is the same classList error we fixed in earlier modules.
✅ The Golden Rule
Load third-party CDN libraries in the <head> so they are available when needed. Put your own JS logic just before </body> so the full DOM exists before you touch it.
Topic 3 · QR Code Generation
Meet the QRious Library
QRious is a lightweight third-party JavaScript library that generates QR codes using pure JavaScript — no server, no plugin, no image upload needed.
📦 Step 1 — Import via CDN
Add this inside the <head> of your HTML. This loads the QRious library from the internet so you can use its QRious class in your code.
html
<script src="https://cdnjs.cloudflare.com/ajax/libs/qrious/4.0.2/qrious.min.js"></script>
🎁 The Gift Wrapper Analogy
Think of QRious as a skilled gift wrapper. You hand it a box (the input text) and choose the paper size (the size option). The wrapper does the complex folding and taping in the background and hands you back a fully wrapped gift (the QR code image) that you can display instantly.
QRious() Options
valueStringThe text or URL to encode into the QR code
sizeNumberWidth & height of the QR code in pixels — 400 is a good web standard
levelStringError correction level: 'L' Low (7%) · 'M' Medium (15%) · 'Q' Quartile (25%) · 'H' High (30%)
Topic 3 · Step 2
Structure the HTML Interface
Three elements are needed: an input field, a trigger button, and an image placeholder.
html
<!-- Input field for user text or URL -->
<input type="text" id="qr-code-value" placeholder="Enter text or URL">

<!-- Button that triggers the generation -->
<button onclick="generateQRCode()">Generate QR Code</button>

<!-- Placeholder image where QR code will appear -->
<img id="qr-code-image" alt="QR Code">
📝 <input type="text">
  • id="qr-code-value" — lets JS select it
  • placeholder — hint text shown when empty
  • .value property reads what the user typed
🛎️ <button onclick>
  • onclick="generateQRCode()" calls our function when clicked
  • Alternative: use addEventListener("click", ...) from M11
  • Both approaches work identically here
🖼️ <img id="qr-code-image">
  • Starts empty — no src attribute yet
  • JS will inject the QR code as a Data URL into the src
  • The browser renders it as an image automatically
Topic 3 · Step 3
The JavaScript Logic
Five steps inside generateQRCode() — read input, configure options, create object, convert to image, inject into DOM.
javascript
function generateQRCode() {

  // Step 1: Get the user's input from the text field
  const value = document.getElementById('qr-code-value').value;

  // Step 2: Set up the options dictionary
  const options = {
    value: value,   // The text/URL to embed
    size:  400,    // Width/height of the QR code in pixels
    level: 'H'    // Error correction level ('H' = High = 30% resilience)
  };

  // Step 3: Create a new QRious object using the options
  const qrCode = new QRious(options);

  // Step 4: Convert QR code object into a Data URL string
  const qrCodeImage = qrCode.toDataURL();

  // Step 5: Inject the Data URL into the <img> tag's src attribute
  document.getElementById('qr-code-image').src = qrCodeImage;
}
📊 What is a Data URL?
A Data URL is a URI that embeds image data directly as a Base64-encoded string inside the src attribute.

Instead of pointing to a file path like image.png, it looks like:
data:image/png;base64,iVBORw0KGgo...

The browser renders this as a full image — no file saved to disk!
🔒 Error Correction Levels
'L'Low7% recovery 'M'Medium15% recovery 'Q'Quartile25% recovery 'H'High30% recovery ★
'H' means even if ~30% of the QR code is scratched or covered, a scanner can still read it.

FAQs
Common Questions Answered
❓ How do I create a QR code in JavaScript?
The standard approach: create an instance of a QR code object (like new QRious(options)), pass in the text content, and convert that object into an image format using toDataURL(). Different libraries vary in syntax but follow the same pattern.
❓ Can I develop a circular or styled QR code?
Yes! While the basic QRious library creates square codes, you can build custom styles using CSS around the <img> tag (e.g., border-radius: 50% for circular masks). Advanced QR platforms also offer templates to embed logos or circular overlays.
❓ Why use size: 400?
400px is a good standard for web apps — large enough to be easily scanned by a smartphone camera without taking up too much screen space. Smaller values (like 150) are fine for compact UIs; larger values improve readability from a distance.
❓ What does level: 'H' mean?
This sets the Error Correction Level. 'H' (High) means the QR code is resilient to up to 30% damage. Even if part of the image is scratched or covered, a smartphone scanner can still read the data successfully.
❓ Why put the JS before </body> instead of <head>?
Scripts in <head> run before the HTML is rendered — if they try to select DOM elements that don't exist yet, they return null and crash. Placing JS before </body> ensures the full page is loaded first.
