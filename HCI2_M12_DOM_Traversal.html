Topic 1 · DOM Relationships
Understanding the Node Hierarchy
The DOM is a tree of nodes — every element has a position in this hierarchy.
👆 Parent Node
The node immediately above a given node. Every node has exactly one parent (except the root document).
👇 Child Node
Any node directly underneath a parent. A parent can have zero or more children.
↔️ Sibling Nodes
Nodes sharing the same direct parent — at the same level of the hierarchy.
🌳 Ancestors & Descendants
Ancestors = all nodes above · Descendants = all nodes below
PropertyDescriptionReturns
parentNode / parentElementDirect parent (node / element variant)Node / Element
children ✅HTML element children only — excludes #text whitespaceHTMLCollection
childNodesAll child nodes including text & whitespaceNodeList
firstElementChild ✅First child that is an HTML elementElement
lastElementChild ✅Last child that is an HTML elementElement
nextElementSibling ✅Next sibling HTML element · returns null if noneElement / null
previousElementSibling ✅Previous sibling HTML element · returns null if noneElement / null
⚠️ #text node trap: childNodes, firstChild, and lastChild include whitespace and newlines as #text nodes. Always use the Element variants (✅) to target actual HTML tags.

Building, Inserting & Cloning Nodes
MethodDescription

parent.appendChild(node)Adds node as the last child of parent
parent.insertBefore(new, ref)Inserts new node directly before a reference sibling
parent.removeChild(child)Removes a specified child node from the tree
parent.replaceChild(new, old)Replaces an existing child with a new node

🔧 createElement — 3-Step Workflow
1Create — document.createElement("div") 2Configure — set innerHTML, className, style 3Attach — parent.appendChild(newEl)
Until step 3, the element exists only in memory — invisible on the page.
📚 Real-World Patterns
  • Dynamic Todo Lists — event.target.parentElement.remove() deletes a row without needing unique IDs
  • Dropdown Menus — element.nextElementSibling.classList.toggle("show")
  • Breadcrumb Nav — traverse up via parentNode to build hierarchy trails
Topic 2 · Event Listeners
What Is an Event Listener?
A procedure in JavaScript that waits for an event to occur.
🔔 Definition
An event listener is a procedure in JavaScript that waits for a specific event to occur.

A simple example of an event is a user clicking the mouse or pressing a key on the keyboard.

The addEventListener() method of the EventTarget interface sets up a function that will be called whenever the specified event is delivered to the target.
🎯 Common Event Targets
You can listen for events on any DOM object — not just HTML elements:
  • Element — any HTML tag on the page
  • Element.children — child elements of a parent
  • Document — the entire HTML document
  • Window — the browser window object
  • XMLHttpRequest — for AJAX requests
✨ Key Benefits of addEventListener()
▸ Attaches a handler without overwriting existing handlers ▸ Add multiple handlers of the same type to one element ▸ Works on any DOM object (window, document, XMLHttpRequest) ▸ Keeps JavaScript separated from HTML markup ▸ Easier to control event bubbling behavior ▸ Easily remove listeners with removeEventListener()
Topic 2 · Event Listeners
addEventListener() Syntax & Parameters
element.addEventListener(event, function, useCapture);
event The type of event to listen for — a string such as "click", "mousedown", "keydown", or any other valid HTML DOM Event. Required
function The callback function we want to call when the event occurs. This is the code that runs in response to the event. Required
useCapture A boolean value specifying whether to use event bubbling (false, default) or event capturing (true). This parameter is optional. Optional
💬 Common Event Types
"click" — mouse click "dblclick" — double click "mousedown" — mouse pressed "mouseup" — mouse released "keydown" — key pressed "keyup" — key released "submit" — form submitted "input" — input changed "mouseover" — hover enter "load" — page/resource loaded
🔄 Bubbling vs Capturing
Bubbling (default)
Event travels up from target → ancestors
useCapture: false
Capturing
Event travels down from root → target
useCapture: true
Sample Code 1 · Date Display
Click to Show Current Date
A button click fires a named function that injects the current date into a paragraph using innerHTML.
html
<!DOCTYPE html>
<html>
<body style="background-color: bisque;">

  <h1 style="text-align:center; color: brown; font-style: oblique;">My Blog Site</h1>

  <p style="text-align: center;">This site is regarding about my daily activities
  and also this serve as my portfolio</p>

  <button id="Btn">DATE</button>

  <p id="1"></p>

  <script style="text-align: center;">
    document.getElementById("Btn").addEventListener("click", displayDate);

    function displayDate() {
      document.getElementById("1").innerHTML = Date();
    }
  </script>

</body>
</html>
🔑 What's Happening
  • The button with id="Btn" is selected by getElementById
  • addEventListener("click", displayDate) registers a named function as the handler
  • When clicked, displayDate() fires and sets innerHTML of the <p id="1"> to the current date & time via JavaScript's built-in Date()
💡 Named Function vs Anonymous
Here a named function (displayDate) is passed as the handler — it can be referenced and removed later with removeEventListener("click", displayDate).

Anonymous functions function() {...} cannot be removed once registered.
Sample Code 2 · Skill-Building
Click to Show Welcome Alert
An anonymous function is passed directly into addEventListener to trigger an alert dialog on click.
html
<!DOCTYPE html>
<html>
<body style="background-color: bisque;">

  <h1 style="text-align:center; color: brown; font-style: oblique;">My Blog Site</h1>

  <p style="text-align: center;">This site is regarding about my daily activities
  and also this serve as my portfolio</p>

  <button id="Btn">Click Here</button>

  <script>
    document.getElementById("Btn").addEventListener("click", function() {
      alert("Welcome to my Site");
    });
  </script>

</body>
</html>
🔑 What's Happening
  • Same pattern — getElementById("Btn") selects the button
  • This time an anonymous function is passed directly as the second argument
  • When clicked, alert("Welcome to my Site") fires a browser dialog box
  • No separate named function needed for simple one-off actions
⚠️ Key Rule — No Duplicate Listeners
If the same function or object is already in the list of event listeners for the same event type on the same target, it is not added a second time.

This prevents accidental duplicate event firing when code runs more than once.

🔔 Doorbell Analogy — Event Listener
An event listener is like a doorbell:
  • The button = the HTML element being watched
  • Pressing it = the event (e.g., "click")
  • The chime inside = the callback function that runs
  • You can add multiple chimes to one button — all fire on press
✅ Use Case 1 — Dynamic Todo Lists
Each “Delete” button uses event delegation on the parent container. event.target.parentElement.remove() deletes the entire task row without needing IDs on every item.
💬 Use Case 2 — Interactive Forms
Listen for "input" events on a text field to validate in real time. Highlight in red with element.style.borderColor = "red" as the user types.
🔐 Use Case 3 — Modal Dialogs
Listen for a "click" on a Close button, then removeEventListener after dismissal so the dialog cannot be closed twice accidentally.

  • Remove with removeEventListener()
💡 Code Patterns Covered
  • Named function handler → getElementById("Btn").addEventListener("click", displayDate)

Answer Key · All Items
Answers & Explanations
Multiple Choice (1–5)
1
B — children
element.children returns an HTMLCollection of element-type children only. childNodes includes #text whitespace nodes created by HTML indentation.
2
B — A procedure that waits for an event to occur
Exact definition from the module. Events include mouse clicks, key presses, and any other user or system action delivered to a DOM target.
3
C — insertBefore()
Syntax: parent.insertBefore(newNode, referenceNode). Inserts newNode immediately before the reference child inside the parent.
4
C — The targeted event type (e.g., "click")
The first argument is always the event type string. The second is the callback function. The optional third is the useCapture boolean.
5
B — null
nextElementSibling returns null (not undefined) when there is no following sibling element. Always guard with: if (next) { ... } before accessing properties on it.
Identification (1–5)
1
nextElementSibling
The "Element" variant skips invisible text nodes from indentation. nextSibling would often land on a #text node instead of the next tag.
2
EventTarget
The EventTarget interface is implemented by any object that can receive events. All DOM elements, Document, and Window implement EventTarget.
3
appendChild()
The final step of the 3-step createElement workflow. Without this, the new element exists only in memory and is invisible on the rendered page.
4
element.remove()
Modern DOM API shorthand. Equivalent to element.parentNode.removeChild(element) but far more concise and readable.
5
removeEventListener()
Must be called with the same event type and the exact same function reference. Anonymous functions cannot be removed this way since they have no referenceable name.
