Review · FAQs
Common Questions Answered
❓ Why use addEventListener over inline onclick?
  • Multiple handlers — addEventListener stacks; onclick replaces
  • Separation of concerns — keeps JS logic out of HTML markup
  • Removable — can be detached with removeEventListener()
  • Any target — works on window, document, or any element
❓ What is the #text node trap with childNodes / firstChild?
HTML indentation and newlines between tags become #text nodes. Targeting firstChild often lands on invisible whitespace.

Fix: Always use the Element variants: children, firstElementChild, lastElementChild, nextElementSibling.
❓ Are all NodeLists static?
No. querySelectorAll() returns a static NodeList — a snapshot. But element.childNodes returns a live NodeList that updates automatically when the DOM changes.
❓ Why doesn't .forEach() work on getElementsByClassName()?
getElementsByClassName() returns an HTMLCollection — no built-in .forEach(). Convert it first:

Array.from(collection).forEach(...)  ·  or use querySelectorAll() which returns a NodeList with native forEach.
❓ What is the main DOM vs HTML difference?
HTML is static text markup — a file describing structure. The DOM is the browser's live, in-memory object representation generated from that HTML, exposing a JavaScript API to read and modify the page at runtime.

Synthesis Drill · Full Project
Task List Manager
One complete app combining all four pillars: selection, manipulation, events, and parent-node deletion.
html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Task List Manager</title>
</head>
<body>
  <input type="text" id="taskInput" placeholder="Enter task...">
  <button id="addBtn">Add Task</button>
  <div id="taskList"></div>

  <script>
    // 1. Selection
    const input     = document.querySelector("#taskInput");
    const addBtn    = document.querySelector("#addBtn");
    const container = document.querySelector("#taskList");

    // 2. Event: Add Task
    addBtn.addEventListener("click", function() {
      const taskText = input.value.trim();
      if (taskText === "") { alert("Enter a valid task!"); return; }

      // 3. Manipulation: Create → Configure → Append
      const row = document.createElement("div");
      row.className = "task-row";
      row.innerHTML = "<span>" + taskText + "</span>";
      container.appendChild(row);
      input.value = "";
    });

    // 4. Event Delegation: Delete via parentElement
    container.addEventListener("click", function(event) {
      if (event.target.classList.contains("delete-btn")) {
        event.target.parentElement.remove();
      }
    });
  </script>
</body>
</html>
Synthesis Drill · Breakdown
Four Pillars in One App
🔍 Pillar 1 — Selection
  • querySelector("#taskInput") — gets the text input
  • querySelector("#addBtn") — gets the Add button
  • querySelector("#taskList") — gets the container div

Modern CSS-selector syntax — works for IDs, classes, or any valid selector.
✏️ Pillar 2 — Manipulation
  • createElement("div") — creates a new task row node
  • row.className = "task-row" — sets its class
  • row.innerHTML = ... — injects span + button markup
  • container.appendChild(row) — attaches it to the DOM
  • input.value = "" — clears the text field after add
⚡ Pillar 3 — Event Handling
  • addBtn.addEventListener("click", fn) — triggers task creation
  • input.value.trim() — validates the field isn't empty
  • alert() — provides immediate user feedback
  • Handler registered without overwriting existing listeners
🌳 Pillar 4 — Traversal + Delegation
  • Event Delegation — one listener on container handles all delete buttons, even dynamically added ones
  • event.target.classList.contains("delete-btn") — confirms correct element was clicked
  • event.target.parentElement — navigates UP to the task row
  • .remove() — modern self-removal shorthand

🌳 DOM Fundamentals
  • DOM = browser's live in-memory tree from HTML
  • W3C Standard: Core · XML · HTML DOM
  • HTML = static file · DOM = live programmable object
  • Every element is a node with properties & methods

  • Bubbling (false) vs Capturing (true)
  • Delegation: listen on parent · check event.target

  • HTMLCollection — live, elements only, no forEach
  • NodeList — usually static, any node type, has forEach
  • Array.from(col) or [...col] → true Array
  • Live loop trap: indices shift when items removed
🔑 The Rules That Prevent 90% of DOM Bugs
▸ Prefer children over childNodes — skip #text nodes ▸ querySelector returns null — always null-check ▸ nextElementSibling returns null — guard before use ▸ Live collections shift mid-loop — convert or iterate in reverse ▸ addEventListener stacks — onclick= overwrites ▸ createElement alone is invisible — must appendChild

Answer Key · Page 1 of 2
Answers 1 – 5
1
B — Document Object Model
DOM = Document Object Model. The browser-generated, live in-memory tree representation of an HTML page, exposing a JavaScript programming API.
2
C — HTML DOM
The W3C DOM has 3 parts: Core DOM (all documents), XML DOM (XML files), and HTML DOM — which defines HTML elements as objects with properties, methods, and events.
3
B — element.innerHTML
innerHTML gets or sets the HTML markup content inside an element. element.style targets CSS, setAttribute() sets attributes, createElement() creates new nodes.
4
A — document.getElementById()
getElementById() selects a single unique element by its id attribute. getByClassName and querySelectorAll return collections, not a single element.
5
B — Attaching an event handler callback to a target element
addEventListener() registers a callback that fires when a specified event occurs on the target. It does NOT create elements, remove nodes, or iterate collections.
Answer Key · Page 2 of 2
Answers 6 – 10
6
B — The targeted event name (e.g., "click", "mouseover")
The first argument of addEventListener is always the event type string. The second is the callback function. The optional third is the useCapture boolean.
7
C — element.parentNode
parentNode moves one level UP the DOM tree to the direct parent. children moves DOWN (to child elements), nextElementSibling moves sideways, childNodes returns all child nodes including #text.
8
B — children
element.children returns an HTMLCollection of HTML element children only. childNodes includes #text whitespace nodes. firstChild and nextSibling also include text nodes.
9
B — A static NodeList
querySelectorAll() returns a static NodeList snapshot. DOM changes after the query do not update it. getByClassName/getByTag return live HTMLCollections. childNodes returns a live NodeList.
10
B — document.createElement()
createElement() instantiates a new element node in memory. It must be appended with appendChild() to appear on the page. appendChild alone cannot create — only attach.
