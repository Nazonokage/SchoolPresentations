Topic 1 · Execution Models
Synchronous vs Asynchronous
⌛ Synchronous
Code runs line-by-line in a single thread. Each instruction must complete before the next begins.

If a script downloads data from a remote server, the entire page UI freezes until the download finishes.
⚡ Asynchronous
Time-consuming operations run in the background. The main thread stays free to handle user clicks, animations, and input.

When the background task completes, a callback or Promise resolution delivers the result.
ConceptSynchronousAsynchronous
Execution FlowLine-by-line, sequential orderNon-blocking, runs concurrently in background
UI ResponsivenessFreezes during long-running tasksRemains responsive while background tasks complete
Primary Use CasesMath logic, local data transformationNetwork requests, hardware access, database queries
⚠️ Standard JavaScript runs on a single thread. Any synchronous operation that blocks for 3+ seconds completely locks the browser — no clicks, scrolling, or animation will work.
Topic 2 · Server APIs — AJAX & fetch()
Fetching Data with fetch()
AJAX = Asynchronous JavaScript and XML — a technique to fetch or send data to remote servers without a full page reload. Modern AJAX uses JSON, not XML.
javascript
fetch('https://api.example.com/data')
  .then(function(response) {
    // ⚠️ fetch() ONLY rejects on network failure — NOT on 404/500
    if (!response.ok) {
      throw new Error('HTTP Error Status: ' + response.status);
    }
    return response.json(); // Parses JSON payload into a JS Object
  })
  .then(function(data) {
    console.log('Retrieved Data:', data);
  })
  .catch(function(error) {
    console.error('Network/Fetch Error:', error);
  });
🟢 Step 1 — fetch(url)
Sends HTTP GET in the background. Returns a Promise<Response> immediately — execution continues without waiting.
🟡 Step 2 — response.json()
The first .then() gives you the Response object, not the data yet. Call .json() to parse it — returns another Promise.
🟣 Step 3 — Use data / .catch()
Second .then() receives the parsed JS object. .catch() handles both network failures and manually thrown errors.
⚠️ Critical: A 404 or 500 HTTP response does NOT reject the Promise. Always check if (!response.ok) and throw manually!
Topic 2 · Promises
The Promise Lifecycle
A Promise represents an async operation that hasn't finished yet but is expected to complete in the future.
⏳
Pending
Initial state. The operation is still in progress.
→
✅
Fulfilled
Operation succeeded. .then() fires with the result.
→
❌
Rejected
Operation failed. .catch() fires with the error.
⛓️ Promise Chain Methods
  • .then(result => ...) — runs when fulfilled; chainable
  • .catch(error => ...) — catches any rejection in the chain above
  • .finally(() => ...) — runs regardless of outcome (cleanup)
  • Each .then() can return a new Promise — enabling chained async steps
⚠️ Common Promise Mistakes
  • Missing .catch() — unhandled rejections fail silently
  • Not returning response.json() — breaks the chain
  • Treating the first .then() as the data — it's the Response object
  • Assuming 404/500 rejects — they don't; check response.ok
Topic 3 · Device Web APIs
Hardware Access with getUserMedia()
Unlike Server APIs that query remote databases, Device APIs interface directly with hardware on the user's machine — webcam, microphone, GPS.
javascript
// Requesting access to the user's camera
navigator.mediaDevices.getUserMedia({ video: true, audio: false })
  .then(function(stream) {
    const videoElement = document.querySelector('video');
    videoElement.srcObject = stream; // Attach live stream to <video> tag
  })
  .catch(function(error) {
    console.error('Camera access denied or unavailable:', error);
  });
📷 How getUserMedia() Works
  • Accepts a constraints object { video: true, audio: false }
  • Returns a Promise<MediaStream>
  • Browser shows a permission pop-up — user must explicitly approve
  • On approval: attaches the stream to a <video> via srcObject
  • On denial: Promise rejects → .catch() handles the error
🔒 Security Requirement
Hardware Device APIs like getUserMedia() require a secure context — either HTTPS or localhost.

They will silently fail or be unavailable on plain http:// sites.
📹 Practical Use Cases
  • Video conferencing (Google Meet, Zoom Web)
  • Profile photo capture via webcam
  • QR code / barcode scanning in the browser
  • Voice recording or transcription apps

Topic 4 · Working with Storage
localStorage & sessionStorage Methods
Both use identical methods — only their persistence scope differs.
javascript
// ── 1. Basic CRUD Operations ───────────────────────────────────
localStorage.setItem('theme', 'dark');
const currentTheme = localStorage.getItem('theme'); // "dark"
localStorage.removeItem('theme');
localStorage.clear();                               // Clears ALL items for this origin

// ── 2. Storing Objects — MUST use JSON.stringify() ─────────────
const userProfile = { name: 'Alex', role: 'Developer' };

localStorage.setItem('user', JSON.stringify(userProfile));

// ── 3. Reading Objects — MUST use JSON.parse() ─────────────────
const storedUser = JSON.parse(localStorage.getItem('user'));
console.log(storedUser.name); // Output: "Alex"

// ── ⚠️ WITHOUT JSON.stringify — broken result ─────────────────
localStorage.setItem('bad', userProfile);
localStorage.getItem('bad'); // "[object Object]" — unusable!
📚 Bookshelf Analogy — localStorage
localStorage is like a home bookshelf: books stay there indefinitely until you physically remove them. Even closing the browser and coming back days later — your data persists.
🏨 Hotel Notepad Analogy — sessionStorage
sessionStorage is like a hotel room notepad: anything written is cleared as soon as you check out and close the tab. A new tab = a fresh notepad.
Topic 4 · Cookie Security
HTTP Cookie Security Flags
Cookies support specialized flags to protect sensitive data from attacks.
HttpOnly
Blocks client-side JavaScript (document.cookie) from reading the cookie. Mitigates Cross-Site Scripting (XSS) attacks where malicious scripts attempt to steal session tokens.
Secure
Restricts cookie transmission to encrypted HTTPS requests only. Prevents the cookie from being sent over insecure HTTP connections where it could be intercepted.
SameSite
Controls cross-site request handling to mitigate Cross-Site Request Forgery (CSRF) attacks. Values: Strict (same origin only) · Lax (allows safe cross-site) · None (unrestricted, requires Secure).
FlagThreat BlockedEffect
HttpOnlyXSS (Cross-Site Scripting)JS cannot read cookie via document.cookie
SecureNetwork interception / MITMCookie only sent over HTTPS
SameSite=StrictCSRF (Cross-Site Request Forgery)Cookie never sent on cross-origin requests
Guided Drill · Full Project
Camera & Storage Demo App
Combines getUserMedia() for webcam, localStorage for theme, and Canvas for photo capture.
html
<!DOCTYPE html>
<html lang="en"><head><meta charset="UTF-8"><title>Camera & Storage Module</title>
<style>
  body.light { background:#f4f4f9; color:#222; font-family:sans-serif; padding:20px; }
  body.dark  { background:#1e1e2f; color:#fff; font-family:sans-serif; padding:20px; }
  video, canvas { width:300px; height:225px; border:2px dashed #888; border-radius:6px; }
</style></head>
<body class="light">
  <h2>Device & Web Storage Demo</h2>
  <button id="theme-btn">Toggle Theme</button>
  <button id="cam-btn">Start Camera</button>
  <button id="snap-btn">Take Photo</button>
  <div><video id="webcam" autoplay playsinline></video>
  <canvas id="snapshot"></canvas></div>
  <script>
    // 1. localStorage Theme Management
    const savedTheme = localStorage.getItem('appTheme') || 'light';
    document.body.className = savedTheme;
    document.getElementById('theme-btn').addEventListener('click', function() {
      const newTheme = document.body.className === 'light' ? 'dark' : 'light';
      document.body.className = newTheme;
      localStorage.setItem('appTheme', newTheme); // Persist preference
    });

    // 2. Device API — getUserMedia
    const video  = document.getElementById('webcam');
    const canvas = document.getElementById('snapshot');
    document.getElementById('cam-btn').addEventListener('click', function() {
      navigator.mediaDevices.getUserMedia({ video: true })
        .then(function(stream) { video.srcObject = stream; })
        .catch(function() { alert('Could not access camera hardware.'); });
    });

    // 3. Canvas Frame Capture
    document.getElementById('snap-btn').addEventListener('click', function() {
      canvas.getContext('2d').drawImage(video, 0, 0, canvas.width, canvas.height);
    });
  </script>
</body></html>
Guided Drill · Breakdown
Three Systems Working Together
💾 Part 1 — localStorage Theme
  • localStorage.getItem('appTheme') reads saved theme on page load
  • Falls back to 'light' with || 'light' if no value exists yet
  • Sets document.body.className to apply the CSS class
  • On toggle: saves the new theme back with setItem
  • Theme persists across page refreshes — that's localStorage's power
📷 Part 2 — getUserMedia
  • Calls navigator.mediaDevices.getUserMedia({ video: true })
  • Browser shows a permission pop-up asking the user to allow camera
  • On approval: Promise fulfills with a MediaStream object
  • Assign to video.srcObject to display live feed in the <video> tag
  • .catch() handles denial or hardware unavailability
🖼️ Part 3 — Canvas Snapshot
  • Gets the 2D rendering context: canvas.getContext('2d')
  • Calls drawImage(video, 0, 0, width, height) to capture the current video frame
  • The canvas now holds a static image snapshot of that exact moment
  • Can be exported as PNG via canvas.toDataURL() and uploaded via fetch()
💡 Real-world combo: This pattern — getUserMedia + Canvas + fetch() — powers profile photo capture tools, ID verification apps, and video snapshot features in production web apps.
FAQs
Common Questions Answered
❓ Why does getUserMedia() fail on my HTTP testing site?
Modern browsers enforce strict security protocols for hardware access. getUserMedia() requires a secure context — either HTTPS or localhost. It will fail silently or be unavailable on plain http:// sites.
❓ Can I store passwords or access tokens in localStorage?
No. Any JavaScript running on the page can read localStorage, making it vulnerable to Cross-Site Scripting (XSS) attacks. Sensitive authorization tokens are safer in HttpOnly cookies which are invisible to JavaScript.
❓ What happens if I store an object without JSON.stringify()?
JavaScript automatically coerces the object into a string, resulting in the useless text value "[object Object]". Always use JSON.stringify() before storing and JSON.parse() when reading objects.
❓ Does fetch() reject on 404 or 500 errors?
No. fetch() only rejects on network failures (total connectivity loss). HTTP error codes like 404 or 500 still fulfill the Promise. Always manually check if (!response.ok) before processing data.
❓ What is the difference between localStorage and sessionStorage?
localStorage persists until explicitly cleared — survives browser restarts. sessionStorage is cleared automatically when the tab or browser session closes. Both are client-side only and are never sent to the server.

Answer Key
Answers & Explanations
1
C — navigator.mediaDevices.getUserMedia()
getUserMedia() accesses media input devices like cameras and microphones, returning a Promise<MediaStream>. fetch() retrieves remote data, localStorage stores strings, and document.cookie manages cookies.
2
B — Serialized to a JSON string using JSON.stringify()
localStorage stores values exclusively as strings. Non-primitive types (objects, arrays) must be converted with JSON.stringify() before storing and JSON.parse() when reading. Skipping this produces the useless "[object Object]" string.
3
C — HttpOnly
HttpOnly prevents document.cookie from reading the cookie via JavaScript, mitigating XSS attacks. Secure restricts transmission to HTTPS. SameSite prevents CSRF. Domain controls which host receives the cookie.
4
B — No; fetch() only rejects on network failures
fetch() resolves as long as the request reaches the server and receives any response — including 404 and 500. Developers must check if (!response.ok) and throw manually. fetch() only rejects on total network failures like no connectivity.
