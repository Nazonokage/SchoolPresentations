Core Concept

What Are CRUD Operations?

CRUD is the standard vocabulary for interacting with any persistent database. Every web application — from social media to banking — is built on these four operations.

LetterOperationSQL CommandPurpose
CCreateINSERT INTOAdd new records to a table
RReadSELECTRetrieve data for display or analysis
UUpdateUPDATE SETModify specific fields in existing records
DDeleteDELETE FROMRemove records based on specific criteria

⚡ Why Node.js + MySQL?

Node.js provides an asynchronous, event-driven runtime for fast server-side logic. MySQL is a reliable, open-source RDBMS for structured data. Together they power the majority of real-world web applications.

Phase 2 — Database Connection

config.js & db.js — Wiring the Connection

JS — config.js + db.js
// config.js — database credentials
module.exports = {
  host     : 'localhost',
  user     : 'root',
  password : 'your_password', // replace this
  database : 'shop_db'
};

// ─────────────────────────────────────────

// db.js — reusable connection module
const mysql  = require('mysql');
const config = require('./config');

const connection = mysql.createConnection(config);

connection.connect((err) => {
  if (err) {
    console.error('Connection failed:', err.message);
    process.exit(1); // stop the app on failure
  }
  console.log('✅ Connected to MySQL — shop_db');
});

module.exports = connection;

🔌 Connection Breakdown

1

Separate config from logic

Keeping credentials in config.js means you only update one file when credentials change — no hunting through code.

2

mysql.createConnection()

Accepts an object with host, user, password, database. Returns a connection object used for all queries.

3

process.exit(1) on failure

If the connection fails on startup, there's no point continuing. Exit immediately with a non-zero code so the system knows the app crashed.

4

module.exports = connection

Exporting the connection object lets crud.js import and reuse it — no need to reconnect for every operation.

⚠️ createConnection vs createPool: For learning, createConnection is perfect. In production, use mysql.createPool() to reuse a set of connections and handle concurrent requests efficiently.
Phase 3 — Security First

Parameterized Queries — Never Skip This

SQL Injection is the #1 web security vulnerability. It happens when user input is concatenated directly into SQL strings, letting attackers manipulate your database.

❌ Vulnerable — DO NOT DO THIS
const id = req.body.id; // Attacker sends: // id = "1 OR 1=1; DROP TABLE products; --" // This wipes your entire products table! connection.query( "SELECT * FROM products WHERE id = " + id // User input directly in SQL string = disaster );
✅ Safe — Always Use This Pattern
const id = req.body.id; // The ? is a placeholder. // mysql driver escapes the value before // substituting it — injection neutralized. connection.query( "SELECT * FROM products WHERE id = ?", [id], // values array — separate from SQL (err, results) => { ... } );

🛡️ How ? Escaping Works

The mysql module wraps string values in quotes and escapes special characters. Even if a user types '; DROP TABLE--, it becomes a harmless string literal.

📋 Full Security Checklist

  • Always use ? placeholders
  • Validate data types before querying
  • Store credentials in .env files
  • Handle every err argument

🔑 Credential Safety

Never push passwords to GitHub. Install dotenv, create a .env file, and add it to .gitignore. Read values via process.env.DB_PASS.

Phase 4 — CRUD · Create

Create — INSERT INTO products

JS — Create Operation
// crud.js — CREATE section
const connection = require('./db');

/**
 * Creates a new product record.
 * @param {object} product - { name, price, stock }
 */
const createProduct = (product) => {
  const sql = 'INSERT INTO products SET ?';

  connection.query(sql, product, (err, result) => {
    if (err) {
      console.error('CREATE error:', err.message);
      return;
    }
    console.log(
      `✅ Product created — ID: ${result.insertId}`
    );
  });
};

// Usage: insert a new product
createProduct({
  name  : 'Wireless Keyboard',
  price : 49.99,
  stock : 100
});

createProduct({
  name  : 'USB-C Hub',
  price : 29.50,
  stock : 250
});

🔵 Create — Key Points

1

INSERT INTO ... SET ?

Passing an object to SET ? auto-expands it into name='...', price=..., stock=... — no need to list columns manually.

2

result.insertId

After a successful INSERT, MySQL returns the auto-incremented primary key in result.insertId. Use it to immediately reference the new row.

3

Object keys = column names

The object property names must exactly match your table column names. Mismatches cause a ER_BAD_FIELD_ERROR.

Phase 4 — CRUD · Read

Read — SELECT FROM products

JS — Read Operation
// crud.js — READ section
const connection = require('./db');

// READ ALL: fetch every product
const getAllProducts = () => {
  connection.query(
    'SELECT * FROM products',
    (err, results) => {
      if (err) { console.error(err.message); return; }
      console.log('📋 All products:', results);
    }
  );
};

// READ ONE: fetch a single product by ID
const getProductById = (id) => {
  connection.query(
    'SELECT * FROM products WHERE id = ?',
    [id],
    (err, results) => {
      if (err) { console.error(err.message); return; }
      if (results.length === 0) {
        console.log('⚠️ Product not found.');
        return;
      }
      console.log('🔍 Found:', results[0]);
    }
  );
};

// READ FILTER: products below a price
const getAffordable = (maxPrice) => {
  connection.query(
    'SELECT * FROM products WHERE price < ?',
    [maxPrice],
    (err, results) => {
      if (err) { console.error(err.message); return; }
      console.log(`Under $${maxPrice}:`, results);
    }
  );
};

getAllProducts();
getProductById(1);
getAffordable(40);

🟢 Read — Key Points

1

results is always an array

Even a single-row SELECT returns an array. Access the first row with results[0] and always check results.length before using it.

2

Empty = [] not null

If no rows match, results is an empty array []. Check results.length === 0 to handle "not found" gracefully.

3

? for every WHERE value

Even for reads — user-supplied filter values like IDs or search terms must always go through ? placeholders.

]

Phase 4 — CRUD · Update

Update — UPDATE products SET

JS — Update Operation
// crud.js — UPDATE section
const connection = require('./db');

// UPDATE: modify multiple fields at once
const updateProduct = (id, newData) => {
  const sql = 'UPDATE products SET ? WHERE id = ?';

  connection.query(sql, [newData, id], (err, result) => {
    if (err) { console.error(err.message); return; }
    console.log(
      `✏️ Updated ${result.affectedRows} row(s).`
    );
  });
};

// UPDATE: change a single field only
const updatePrice = (id, newPrice) => {
  const sql = 'UPDATE products SET price = ? WHERE id = ?';

  connection.query(sql, [newPrice, id], (err, result) => {
    if (err) { console.error(err.message); return; }
    console.log(
      `💰 Price updated. Changed: ${result.changedRows}`
    );
  });
};

// Usage
updateProduct(1, { name: 'Mech Keyboard Pro', stock: 80 });
updatePrice(2, 24.99);

🟡 Update — Key Points

1

WHERE is not optional

Omitting WHERE from UPDATE modifies every row in the table. Always target a specific ID or condition.

2

Array order matters

[newData, id] maps left-to-right to each ?. Getting the order wrong silently corrupts data with no error.

3

affectedRows vs changedRows

affectedRows = rows matched the WHERE. changedRows = rows where a value actually changed. If new value equals old value, changedRows is 0.

✏️ Updated 1 row(s).
💰 Price updated. Changed: 1
Phase 4 — CRUD · Delete

Delete — DELETE FROM products

JS — Delete Operation
// crud.js — DELETE section
const connection = require('./db');

// DELETE: remove a product by ID
const deleteProduct = (id) => {
  const sql = 'DELETE FROM products WHERE id = ?';

  connection.query(sql, [id], (err, result) => {
    if (err) { console.error(err.message); return; }
    if (result.affectedRows === 0) {
      console.log('⚠️ No product found with that ID.');
      return;
    }
    console.log(
      `🗑️ Deleted ${result.affectedRows} product(s).`
    );
  });
};

// Usage
deleteProduct(1); // removes Wireless Keyboard
deleteProduct(99); // no match — prints warning

// CLOSE: always end the connection last
setTimeout(() => {
  connection.end((err) => {
    if (err) throw err;
    console.log('🔌 Disconnected from MySQL.');
  });
}, 1000);

🔴 Delete — Key Points

1

WHERE is critical

DELETE FROM products with no WHERE deletes every row. No undo. Always double-check the WHERE condition.

2

affectedRows = 0 = no match

MySQL silently succeeds even if no row matched. Always check result.affectedRows to confirm the deletion happened.

3

connection.end() last

Use setTimeout to let async callbacks finish before closing. end() waits for pending queries; destroy() cuts immediately.

🗑️ Deleted 1 product(s).
⚠️ No product found with that ID.
🔌 Disconnected from MySQL.
💡 Soft Delete Pattern: In production, add an is_deleted BOOLEAN DEFAULT 0 column and UPDATE it to 1 instead of permanently removing rows. Safer and auditable.
Phase 5 — Complete Project

crud.js — Everything Together

JS — crud.js (full runnable script)
// crud.js — Complete CRUD for shop_db.products
const mysql = require('mysql');

const connection = mysql.createConnection({
  host: 'localhost', user: 'root',
  password: 'your_password',
  database: 'shop_db'
});

connection.connect((err) => {
  if (err) { console.error(err.message); process.exit(1); }
  console.log('✅ Connected to shop_db');
});

const createProduct = (p) =>
  connection.query('INSERT INTO products SET ?', p,
    (e, r) => e ? console.error(e) : console.log(`✅ Created ID:${r.insertId}`));

const getAllProducts = () =>
  connection.query('SELECT * FROM products',
    (e, r) => e ? console.error(e) : console.log('📋 Products:', r));

const updateProduct = (id, data) =>
  connection.query('UPDATE products SET ? WHERE id = ?', [data, id],
    (e, r) => e ? console.error(e) : console.log(`✏️ Updated ${r.affectedRows} row`));

const deleteProduct = (id) =>
  connection.query('DELETE FROM products WHERE id = ?', [id],
    (e, r) => e ? console.error(e) : console.log(`🗑️ Deleted ${r.affectedRows} row`));

// --- Run the full demo ---
console.log('--- CRUD Demo: shop_db.products ---');

createProduct({ name: 'Wireless Keyboard', price: 49.99, stock: 100 });
createProduct({ name: 'USB-C Hub',        price: 29.50, stock: 250 });
getAllProducts();
updateProduct(1, { price: 44.99, stock: 90 });
deleteProduct(2);
getAllProducts();

setTimeout(() => connection.end(() =>
  console.log('🔌 Disconnected.')
), 1500);

Answer Key — Part 1

Multiple Choice Answers (Q1–7)

Q1: Create operation involves ___ data
✅ C — Inserting
Create maps to SQL's INSERT command — adds new records to a table.
Q2: Read operation involves ___ data
✅ B — Retrieving
Read maps to SELECT — fetches existing data for display or analysis.
Q3: Update operation involves ___ existing data
✅ C — Modifying
Update maps to UPDATE SET — changes values in existing rows.
Q4: Method to close a MySQL connection
✅ D — connection.end()
end() waits for all pending queries to finish before disconnecting gracefully. destroy() cuts immediately without waiting.
Q5: Primary benefit of ? placeholders
✅ B — Prevents SQL Injection
The mysql module escapes values passed via ? — even malicious input like '; DROP TABLE-- becomes a harmless string literal.
Q6: Method to establish a MySQL connection
✅ D — createConnection()
mysql.createConnection(config) accepts host, user, password, database and returns a connection object for executing queries.
Q7: Important to handle ___ in CRUD
✅ C — Errors
CRUD involves network and disk I/O which can fail. Every callback must check the err argument to keep the app stable.

Blank 1: ?   Blank 2: 10   Blank 3: err   Blank 4: err
The ? placeholder keeps the query safe. The value 10 goes in the array. The callback is error-first: (err, results) — err must come before results.
Q9 — Write from Scratch: restockProduct()
✅ Reference solution
JS — Q9 Answer
const restockProduct = (id, newStock) => {
  const sql =
    'UPDATE products SET stock = ? WHERE id = ?';
  connection.query(sql, [newStock, id],
    (err, result) => {
      if (err) { console.error(err.message); return; }
      console.log('Rows affected:', result.affectedRows);
