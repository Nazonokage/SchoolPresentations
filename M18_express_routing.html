Core Concept

What Is Routing?

Routing defines how your application's endpoints (URLs) respond to client requests. It connects an incoming HTTP method + URL path to a specific callback function called a Route Handler.

app . METHOD ( PATH , HANDLER );
app
Express instance
METHOD
get, post, put, delete...
PATH
'/users', '/about', '/:id'
HANDLER
(req, res) => callback
Client
Browser / App

app.get('/users')

req — Request Object

Contains everything about the incoming request: URL, method, body, headers, params, query strings.

res — Response Object

Used to send data back: res.send(), res.json(), res.render(), res.redirect().

Route Handler

The callback function that runs when the method + path matches. Can be a single function or a chain of middleware.

HTTP Methods

The Six Core HTTP Verbs

HTTP methods define the intended action a client wants to perform. Use the right verb for the right operation to build a predictable, RESTful API.

GET
Retrieve
Fetch data — web pages, user lists, product details. Does not modify data. Safe and idempotent.
POST
Submit / Create
Send new data to the server — creating accounts, posting comments, submitting forms.
PUT
Replace
Replace an entire resource with new data — e.g. replacing a complete user profile.
DELETE
Remove
Remove a specific resource — deleting a user account or removing a cart item.
PATCH
Partial Update
Update only specific fields — changing just an email without re-sending the full profile.
HEAD
Headers Only
Like GET but returns only headers — used to check if a resource exists or was modified.

Route Design

Paths, Parameters & Route Handlers

1. Static Paths

Match an exact URL string. Simple and predictable.

/about
/users
/login

2. Dynamic Parameters

Capture values from the URL using a colon prefix. Available in req.params.

/users/:id
/posts/:slug
/shop/:category/:id

3. Route Chaining

Handle multiple methods for one path using app.route() — keeps code organized.

app.route('/users')
 .get(handler)
 .post(handler)
 .delete(handler)

URL Parameter Anatomy

http://localhost:3000/users/:id/posts/:postId
← static segments → ← dynamic params →

req.params

Object containing all dynamic URL segments. req.params.id gives you the value from :id in the path.

req.query

Object containing query string values from the URL. /search?q=express gives req.query.q === 'express'.

Implementation

Basic Routing — GET, POST, DELETE

JS — Basic Routes
const express = require('express');
const app     = express();

// Middleware: parse incoming JSON bodies
app.use(express.json());

// 1. GET — root URL
app.get('/', (req, res) => {
  res.send('Hello, World!');
});

// 2. GET — static path
app.get('/users', (req, res) => {
  res.send('Here is a list of all users.');
});

// 3. GET — dynamic parameter (:id)
app.get('/users/:id', (req, res) => {
  const userId = req.params.id;
  res.send(`User info for ID: ${userId}`);
});

// 4. POST — create new user
app.post('/users', (req, res) => {
  const newUser = req.body;
  res.json({
    message : 'User created!',
    user    : newUser
  });
});

// 5. DELETE — remove a user by ID
app.delete('/users/:id', (req, res) => {
  const userId = req.params.id;
  res.send(`User ${userId} deleted.`);
});

app.listen(3000, () =>
  console.log('Server on port 3000')
);

📋 Route Breakdown

1

GET / — Root Handler

The simplest route. res.send() sends a plain string response. Every Express app needs at least this.

2

GET /users/:id — Dynamic

:id captures whatever value appears in that URL segment. Access it via req.params.id.

3

POST /users — Create

express.json() middleware parses the request body so req.body contains the sent JSON. Without it, req.body is undefined.

4

DELETE /users/:id

Same path as GET /users/:id but a different HTTP method — Express routes them to completely different handlers.

Same path, different methods: GET /users/:id and DELETE /users/:id share a path but Express calls different handlers — this is the foundation of REST API design.
Advanced Routing

Route Chaining & Multiple Handlers

JS — app.route() Chaining
const express = require('express');
const app     = express();
app.use(express.json());

// Route chaining: all methods for /users
app.route('/users')
  .get((req, res) => {
    res.json({ message: 'GET: all users' });
  })
  .post((req, res) => {
    res.json({
      message : 'POST: user created',
      data    : req.body
    });
  });

// Route chaining with params: /users/:id
app.route('/users/:id')
  .get((req, res) => {
    res.json({ message: `GET user ${req.params.id}` });
  })
  .put((req, res) => {
    res.json({
      message : `PUT: replaced user ${req.params.id}`,
      data    : req.body
    });
  })
  .patch((req, res) => {
    res.json({
      message : `PATCH: updated user ${req.params.id}`,
      data    : req.body
    });
  })
  .delete((req, res) => {
    res.json({
      message: `DELETE: removed user ${req.params.id}`
    });
  });

app.listen(3000, () =>
  console.log('Chained routes on port 3000')
);

🔗 Chaining — Key Points

1

DRY — Don't Repeat the Path

app.route('/users/:id') declares the path once. Each chained method (.get(), .put()) handles its own HTTP verb without repeating '/users/:id'.

2

PUT vs PATCH

PUT replaces the entire record — send all fields. PATCH updates only the fields you send. Use PATCH for small edits like changing an email.

3

res.json() vs res.send()

res.json() automatically sets the Content-Type: application/json header and serializes your object. Use it for API responses; use res.send() for plain strings or HTML.

4

Middleware per route

You can add middleware between the path and handler: app.get('/path', authCheck, handler). The middleware runs first, then calls next() to proceed.

The Post Office
Receives all incoming mail (requests) and routes them to the right handler based on address and mail type.

Reads the address + mail type and decides which mail carrier (handler function) should deliver it.

Lesson Wrap-Up

FAQs & Summary

❓ What is the purpose of routing in Express.js?

Routing lets your application respond differently to each URL + HTTP method combination. Visiting /about loads the About page, submitting to /login authenticates the user — routing connects the URL to the right function.

❓ How do I define a route in Express.js?

Use app.METHOD(path, handler) — e.g. app.get('/', (req, res) => res.send('Hello')). Replace METHOD with the appropriate HTTP verb. The handler receives req and res objects.

❓ Can I have multiple handlers for one route?

Yes — use app.route('/path').get(fn1).post(fn2) for chaining, or pass multiple callbacks: app.get('/path', middleware, handler). The middleware runs first and calls next() to continue.

Answer Key — Part 1

Multiple Choice Answers (Q1–7)

Q1: Which method handles a GET request?
✅ A — app.get()
app.get() is the dedicated Express method for defining route handlers for incoming HTTP GET requests.
Q2: Which method handles a POST request?
✅ B — app.post()
app.post() handles POST requests — typically used to submit data and create new resources on the server.
Q3: Which method handles a PUT request?
✅ C — app.put()
app.put() handles PUT requests — intended to replace an entire existing resource with new data.
Q4: Which method handles a DELETE request?
✅ D — app.delete()
app.delete() handles DELETE requests — used to remove specified resources from the server.
Q5: Express allows routes for different HTTP methods?
✅ A — True
Express provides app.get(), app.post(), app.put(), app.delete(), and more — each routes a specific HTTP verb to its own handler function.
Q6: res.send() sends a response to the client?
✅ A — True
res.send() is the primary response method — it can send strings, JSON, buffers, or HTML and automatically sets appropriate headers.
Q7: res.render() processes templates and sends HTML?
✅ A — True
res.render() works with template engines like EJS or Pug — it processes the template file with given data and sends the generated HTML to the browser.
