Core Concept

What Is an API?

API stands for Application Programming Interface. It's a set of rules and protocols that allows different software systems to communicate with each other — without exposing the internal workings of either system.

🔌 Intermediary

An API sits between two systems. It abstracts away complex internal implementation so developers don't need to know how a third-party service works under the hood.

📋 Standardized Rules

APIs define exactly what requests are accepted, what format data must be in, and what responses will be returned — like a contract between systems.

🔄 Interoperability

Different apps built in different languages (Python, Java, JavaScript) can all talk to the same API because they share a common language: HTTP + JSON.

API Types

The 5 Types of APIs

🌐 Web APIs (REST/HTTP)

Web / RESTful APIs

Communicate over the internet using standard HTTP methods. The backbone of modern web apps — what we build today.

Examples: Twitter API, Google Maps API, GitHub API

📚 Library APIs

Library / Framework APIs

Built-in functions provided by languages or frameworks to help with common tasks.

Examples: JavaScript's Math.sqrt(), Python's print()

🖥️ OS APIs

Operating System APIs

Allow applications to interact with underlying system resources like the file system, network hardware, and device drivers.

Examples: Windows Win32, POSIX on Linux/macOS

🗄️ Database APIs

Database APIs

Allow developers to query, insert, update, and delete data from databases programmatically.

Examples: MySQL driver for Node.js, Mongoose for MongoDB

💳 Third-Party APIs

Provided by external companies to let developers integrate their specific functionalities. Payment gateways (Stripe, PayPal), social logins (Google, Facebook), mapping (Google Maps), weather data, and more.

REST API Design

Anatomy of a REST API

Every REST API request and response has four core components. Understanding these is the foundation of building and consuming any API.

1

Endpoints (URLs)

Specific URLs that represent different resources or functionalities. Each endpoint is a door into your application's data.
/api/users   /api/products/:id

2

HTTP Methods (Verbs)

Specify the action the client wants to perform on the resource.

GET · POST · PUT · DELETE

3

Parameters

Extra data sent with the request to customize the query.

  • URL params: /users/:id
  • Query strings: ?page=2&limit=10
  • Request body: JSON payload
4

Responses

Data the server returns after processing a request — always JSON in REST APIs, always paired with an HTTP status code.

200 OK · 201 Created · 404 Not Found

API vs REST API: "API" is a general term for any interface between two systems. A "REST API" is a specific style that uses HTTP methods, treats data as resources at URLs, and is stateless — each request is independent.
Data Format

JSON — The Language of REST APIs

JSON (JavaScript Object Notation) is the de facto standard for sending and receiving data in web APIs. It's lightweight, human-readable, and natively compatible with JavaScript.

📋 JSON Syntax Rules

Keys in double quotes: "name": "value" — not single quotes

Objects wrapped in curly braces {"{"}{"}"}

Arrays wrapped in square brackets []

Supported types: String, Number, Boolean, Array, Object, null

📄 Valid JSON Example

{

  "isActive": true,

JSON in JavaScript

JSON.stringify() & JSON.parse()

JSON is a string format — not a JavaScript object. To move between the two, JavaScript provides two built-in conversion methods.

JS — Conversion Example
// A plain JavaScript object
const person = {
  name : 'Celestyna Kowalski',
  age  : 28,
  city : 'Krakow'
};

// JSON.stringify() — JS object → JSON string
// Used when SENDING data over the network
const jsonString = JSON.stringify(person);
console.log(jsonString);
// {"name":"Celestyna Kowalski","age":28,"city":"Krakow"}

// JSON.parse() — JSON string → JS object
// Used when RECEIVING data from the network
const parsed = JSON.parse(jsonString);
console.log(parsed.name);  // Celestyna Kowalski
console.log(parsed.age);   // 28
console.log(parsed.city);  // Krakow

// Express does both automatically:
// express.json()  → parses incoming JSON (parse)
// res.json(obj)   → stringifies outgoing obj (stringify)

🔄 When to Use Each

1

JSON.stringify(obj) — Sending Data

Used when sending a JS object over the network — converts to a string the browser's fetch() or HTTP client can transmit.

2

JSON.parse(str) — Receiving Data

Used when receiving a JSON string from a server — converts it back to a JS object so you can access properties with dot notation.

3

Express handles both automatically

express.json() middleware runs JSON.parse() on incoming bodies. res.json() runs JSON.stringify() on your response object.

⚠️ Common mistake: JSON keys must be in double quotes — "name" not 'name'. Single-quoted keys are valid JavaScript but invalid JSON — JSON.parse() will throw an error.
Client Side

Sending JSON to Your API

When a client (browser, mobile app) sends JSON data, it must include two things: the Content-Type: application/json header and the data stringified in the request body.

JS — Client fetch() Request
// Client-side: sending JSON with fetch()
const userData = {
  name  : 'Zbigniew Hartmann',
  age   : 32,
  email : 'z.hartmann@example.com'
};

fetch('/api/users', {
  method  : 'POST',
  headers : {
    'Content-Type': 'application/json'
  },
  body    : JSON.stringify(userData) // ← must stringify!
})
.then(response => response.json())  // parse the response
.then(data => {
  console.log('Server replied:', data);
})
.catch(error => {
  console.error('Error:', error);
});

📤 Request Breakdown

1

method: 'POST'

Tells the server we're creating a new resource. GET is read-only — sending a body with GET is non-standard.

2

Content-Type: application/json

This header tells the server what format the body is in. Without it, the server won't know to parse the body as JSON — req.body will be empty.

3

JSON.stringify(userData)

The body must be a string — not a JavaScript object. JSON.stringify() converts the object to the valid JSON string format required for HTTP transport.

4

.then(res => res.json())

The server sends back a JSON string. .json() on the fetch response parses it back into a JavaScript object so you can use data.message etc.

Server Side

Receiving & Responding with JSON

On the server, add express.json() middleware before your routes — it parses the JSON body and attaches it to req.body.

JS — Express POST Handler
const express = require('express');
const app     = express();

// ✅ MUST come BEFORE your routes
app.use(express.json());

// GET — return a list (read-only)
app.get('/api/users', (req, res) => {
  res.json([
    { id: 1, name: 'Celestyna' },
    { id: 2, name: 'Zbigniew'  }
  ]);
});

// POST — receive JSON body and respond
app.post('/api/users', (req, res) => {
  const userData = req.body; // ← parsed by express.json()

  console.log('Received:', userData);

  // In a real app: save to database here

  // Respond with 201 Created + JSON body
  res.status(201).json({
    message : 'User created successfully',
    data    : userData
  });
});

app.listen(3000, () =>
  console.log('API running on port 3000')
);

⚙️ Server-Side Breakdown

!

express.json() before routes

This middleware runs on every request. If it comes after your routes, the POST handler fires first and req.body is undefined. Order matters.

2

req.body — the parsed data

After express.json() runs, req.body holds your parsed JavaScript object. Access fields directly: req.body.name, req.body.age.

3

res.status(201)

Chain status codes before .json(). 201 Created is the correct REST status for a successful POST that creates a resource — not 200 OK.

4

res.json(object)

Automatically stringifies the object, sets Content-Type: application/json, and sends the response. No manual JSON.stringify() needed.

Real-World Analogy

APIs in the Real World

🍽️ The Restaurant (Third-Party API)

You don't walk into the kitchen and cook yourself. Instead you read the menu (API docs), tell the waiter (endpoint) what you want in plain language {"{"}meal: "steak"{"}"}, and receive your food (JSON response) without ever knowing how the kitchen works.

📺 The Universal Remote (REST/JSON Standard)

JSON + REST acts like a universal remote for software. A TV (Google Maps), a soundbar (Payment API), and a DVD player (Auth API) all speak the same HTTP protocol — so your app can control them all without knowing their internal circuitry.

📱 Real-World Use Cases

Twitter Mobile App

The app doesn't store millions of tweets. It calls GET /tweets to fetch them and POST /tweets to create new ones — all via JSON responses from a REST API.

"Log in with Google"

Clicking that button sends a request to Google's Auth API. If successful, Google returns a unique JSON token — the third-party site never touches your password.

E-Commerce Checkout

Your site POSTs card info to Stripe's API. Stripe processes it and returns {"{"}"status":"success"{"}"} — the website never directly handles sensitive financial data.

Why APIs Matter

Benefits & FAQs

🌟 Key Benefits of APIs

✓

Integration & Interoperability

Different systems built in different languages can communicate via a shared HTTP + JSON protocol.

✓

Modularity & Reusability

Encapsulate functionality (payments, auth, maps) and reuse it across multiple apps without duplication.

✓

Mobile App Support

APIs bridge the mobile UI to the backend server — the app calls an endpoint and renders the JSON data.

✓

Scalability

Frontend and backend can scale independently when connected via a REST API — no tight coupling.

❓ How do I handle incoming JSON in Express?

Add app.use(express.json()) before your routes. This middleware parses the incoming JSON body and makes it available in req.body.

❓ How do I send a JSON response?

Use res.json(object). It automatically sets Content-Type: application/json and stringifies the object — no manual JSON.stringify() needed.

❓ How do I validate JSON data?

express.json() parses but doesn't validate. Use libraries like Joi, Yup, or Validator.js to enforce rules like "email must be valid" or "age must be a number."

Recap

Key Takeaways

🌐 What an API Is

  • Rules/protocols for systems to communicate
  • Acts as a standardized intermediary layer
  • Types: Web, Library, OS, Database, Third-Party

📄 JSON Rules

  • Keys in double quotes only
  • JSON.stringify() — object → string (sending)
  • JSON.parse() — string → object (receiving)

⚙️ Express Middleware

  • app.use(express.json()) before routes
  • Parses body → populates req.body
  • Without it: req.body is undefined

📤 Sending Responses

  • res.json(obj) — auto stringify + headers
  • res.status(201).json(obj) — set status code
  • Use 201 for POST create, 200 for GET

Answer Key — Part 1

Multiple Choice Answers (Q1–7)

Q1: express.json() parses ___ data
✅ C — JSON
express.json() looks for Content-Type: application/json, parses the stringified body, and populates req.body with the resulting JavaScript object.
Q2: Method to send a JSON response
✅ D — res.json()
res.json() is the dedicated method — it reliably sets Content-Type: application/json and stringifies the output. res.send() can accept objects but doesn't guarantee the correct header.
Q3: HTTP method to create a new resource
✅ A — POST
In RESTful architecture, POST is the standard verb for sending data to create a new resource on the server.
Q4: Common data format for REST APIs
✅ A — JSON
While XML was historically used, JSON has become universally preferred for REST APIs due to its lightweight nature and native JavaScript compatibility.
Q5: express.json() parses XML?
✅ B — False
express.json() is exclusively for JSON. Parsing XML requires a third-party package like express-xml-bodyparser.
Q6: Express has built-in HTTP method routing?
✅ A — True
Express includes native methods for every standard HTTP verb: app.get(), app.post(), app.put(), app.delete(), app.patch(), and more — no third-party routing needed.
Q7: Express supports only GET and POST?
✅ B — False
Express supports GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS, and several others — making it fully REST-compatible out of the box.
