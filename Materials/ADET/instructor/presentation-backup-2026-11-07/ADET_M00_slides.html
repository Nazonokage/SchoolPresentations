What is app development?

What happens between an idea and an app on someone’s phone, and where React Native fits.

Trace one idea through the whole process, then explain: shared JavaScript code supports Android and iOS, with platform-specific differences.

Definitions

What is an app?

Application software

A program that does a specific task for a user: pay a bill, check a schedule, order food.

Application development

Creating the program a person or business needs, from first idea to updates.

Mobile app development

Creating apps for phones and tablets, mainly Android (Google, many makers) and iOS (Apple iPhone).

Where users get apps

Google Play for Android and the Apple App Store for iOS. During development you test on your own phone or an emulator first.

Process

The steps of building an app

1 · Requirements

What problem are we solving?

Students queue too long at the registrar.

2 · Design

What will it look like and do?

Sketch a screen with a ticket number.

3 · Build

Make it real.

Write the screens in React Native.

4 · Test

Does it work when things go wrong?

Empty input, no internet.

5 · Release

How do users get it?

App store or a shared build.

6 · Maintain

Fix and improve.

Bug fixes, new features. Real projects loop back to design and testing.

Approaches

Three ways to build a mobile app

Native

Deepest access to the platform. Trade-off: two codebases to maintain.

Cross-platform

React Native, Flutter. Mostly shared code, with some platform differences. You depend on the framework.

Web app

Open from a browser. Trade-off: less access to device features.

Why React Native

Real native screens, written in JavaScript or TypeScript

In plain words

  • Not a web page inside an app
  • You write React components; React Native turns them into native views
  • Expo is a framework and toolset built around React Native: setup, running, device features
The runtime

Who does what on the phone

Hermes is the JavaScript engine, not an AI tool. Shared source does not remove platform testing.

House analogy (not a call diagram)

Your app is the plan, React Native coordinates the rooms and fixtures, and the operating system supplies the building site. It helps you remember roles, not the order of calls.

Expo libraries

Provide supported native services (camera, location and more) through JavaScript APIs. Metro and Expo CLI only prepare and serve code while you develop.

Key terms

Words you will hear

SDK

Software Development Kit: tools and libraries for building apps.

Emulator / simulator

A virtual phone on your computer.

Expo Go

A ready-made app that opens your project during development.

Development build

Your own host app with the native libraries your project needs.

Hermes

The JavaScript engine that runs your code on the phone.

App store

Google Play and the Apple App Store.

Worked example

Predict first: a nicer icon, or fix the data?

Campus queue app

The screen shows tickets correctly but loses them after closing. Is drawing a nicer icon enough? (No)

  1. Requirement: keep the ticket number after reopening
  2. Design: show the current ticket and its status
  3. Build: the screen plus a way to save data
  4. Test: close and reopen, compare with the requirement
  5. Result: losing the ticket fails, however nice it looks
  6. Maintain: repair the data behavior and retest

Misconception

“Shared source guarantees identical behavior on every device.”

Shared code reduces duplication; each platform still needs testing.

Expo Go is a development host, not the finished store release. An SDK supplies tools. Mixing these up means testing the wrong thing.

Analogy & use case

Parang pagpapatayo ng bahay

Kailangan muna ng plano (requirements at design), saka itatayo (build), susuriin (test), ipapakita sa may-ari (release) at aayusin kapag may sira (maintain).

Ang React Native ang kontratistang kayang magtayo sa dalawang lote, Android at iOS, gamit ang halos iisang plano.

Real-world use case

A school builds a queue-ticket app. Some students have Android phones and some have iPhones. One team writes shared screens and ships to both, handling the small platform differences.

Common mistakes

Fix these ideas early

✗ “A web page in a wrapper”

✓ The taught mobile components use native views.

✗ “Expo and React Native compete”

✓ Expo is built around React Native.

✗ “Skip design, just code”

✓ Requirements and design prevent rewrites. Projects loop back as you learn.
