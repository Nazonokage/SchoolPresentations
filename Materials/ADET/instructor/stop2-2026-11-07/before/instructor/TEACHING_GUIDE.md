# Teaching the ADET semester

**Current finals sequence:** M19 rehearsal, [M20 defense quiz and essays](../modules/ADET_M20.md), then [M21 solo mini-capstone announcement and readiness](../modules/ADET_M21.md). Alternating assessments apply through M19. If finals has only two teaching meetings, assign M20 as individual preparation between M19 and M21. Keep summative and periodical exam time separate.

Start with the [student index](../modules/README.md), [environment setup](../examples/README.md), [answer key](ANSWER_KEY.md) and [validation record](VALIDATION.md). The mobile checkpoints share a shell. Select the lesson before class and keep a copy of student modifications before selecting another screen.

| Period | Chapters | Evidence before the periodical |
|---|---|---|
| Prelim | 1–5 | Explain and change a component, input and route |
| Midterm | 6–11 | Trace one task from list to API to database, handle invalid data |
| Pre-final | 12–18 | Add one suitable device capability and finish a personal vertical slice |
| Finals | 19–21 | Repair rehearsal and a runnable solo project presentation |

Two weekday meetings per week give 60–90 minutes each. Reserve a summative meeting before each periodical, including finals. Assign dates only after receiving the actual timetable. Twenty prepared chapters may require combining selected cores. If Prelim has only four content meetings, run M04's validated form and demonstrate M05's route using that form's destination. Grade one task in that meeting. For a short pre-final, show notifications and media as instructor demonstrations and preserve the project integration lab.

**60-minute quiz meeting.** Spend 5 minutes on the campus problem, 20 on the concept and trace, 15 running and changing the screen, 15 on the ten questions and 5 reviewing a common error. M01 begins with introductions and its quiz is diagnostic. **Coding meeting.** Spend 5 minutes predicting, 15 demonstrating, 30 on one individual change and 10 comparing a valid and failing case. At 90 minutes, spend the additional time on setup support, device testing and independent explanations. Avoid adding another graded drill.

Use one backend for an implementation. Pre-seed a private practice dataset and verify phone-to-PC reachability before M07. FastAPI serves HTTP for the SQL track while XAMPP/WampServer supplies the database. For MongoDB use the Node API. Both have the same JSON surface. M11 deliberately models local session behavior. An identity stored on a client is insufficient proof of ownership on either public API.

**Solo evidence.** For M18 require one personal change, the client/API/database diagram and a success/failure trace. For M20 require a clean launch, seed/configuration notes and a five-minute explanation. The rehearsal checklist is a tool for students to record their evidence. Set separate summative and periodical papers and grade those in the assigned slots.

**Device preparation.** Rehearse permission denial and cancellation as well as success. A teacher device can demonstrate the camera and local reminders if students cannot grant permissions on lab devices. Keep a text alternative for the report and a visual label for audio. Use the offline visual assets on the projector. Record class timing and common blockers after the first delivery.
Maintenance: the earlier 20-lesson authoring scripts describe the original sequence. Preserve the published M20 assessment and M21 announcement when regenerating earlier lessons.
