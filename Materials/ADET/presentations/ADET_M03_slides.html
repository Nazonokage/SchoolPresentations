Review M02

State is remembered data for a mounted component. A setter causes the screen to reflect a new value.

Main lesson

Four building blocks

View

A container: groups and positions components.

Text

Displays raw text nodes. Loose text belongs inside Text.

TextInput

Reports what the user types and displays its value.

Button

Accepts a string title and a callback for onPress.

String props such as Button.title are valid. The raw-text rule concerns children outside Text.

Main lesson

Flexbox arranges the boxes

Default direction: column

  • justifyContent follows the main axis.
  • alignItems crosses that axis.
  • Change to row and the axes change.
  • padding is inside space; gap separates children.

StyleSheet gives repeated style objects names; it is not HTML or a CSS stylesheet.

Main lesson

A controlled field keeps UI and data together

value={username}
onChangeText={setUsername}

Predict first

If onChangeText only logs the input, does username change?

No setter means no state update. A label changing elsewhere does not repair that connection.

Main lesson

The exact validation rule

if (username.trim() === "" || password === "") {
  setMessage("Enter both username and password.");
  return;
}
setMessage("Welcome, " + username.trim() + "!");

Read each decision

  • Trim only the username.
  • Reject if either required test is empty.
  • Return stops the success line from replacing the error.
  • No account or server is checked.

Guided program

Complete program: copy once, then trace

import { useState } from "react";
import { View, Text, TextInput, Button, StyleSheet } from "react-native";

export default function App() {
  const [username, setUsername] = useState("");
  const [password, setPassword] = useState("");
  const [message, setMessage] = useState("");

  function handleLogin() {
    // Reject empty username or password
    if (username.trim() === "" || password === "") {
      setMessage("Enter both username and password.");
      return;
    }
    setMessage("Welcome, " + username.trim() + "!");
  }

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Login</Text>
      <TextInput
        style={styles.input}
        placeholder="Username"
        autoCapitalize="none"
        accessibilityLabel="Username"
        value={username}
        onChangeText={setUsername}
      />
      <TextInput
        style={styles.input}
        placeholder="Password"
        secureTextEntry
        accessibilityLabel="Password"
        value={password}
        onChangeText={setPassword}
      />
      <Button title="LOG IN" onPress={handleLogin} />
      <Text>{message}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: "center", padding: 24, gap: 12 },
  title: { fontSize: 28, fontWeight: "bold", textAlign: "center" },
  input: {
    borderWidth: 1,
    borderColor: "#888",
    borderRadius: 8,
    padding: 10,
    fontSize: 16,
  },
});

Find these connections

  • username ↔ its input.
  • password ↔ its input.
  • handleLogin → validation.
  • message → feedback Text.
  • StyleSheet → screen layout.

Use invented credentials. This local demo is not authentication.

Main lesson

Pass the callback; do not call it while rendering

onPress={handleLogin}

What happens on press?

The native button invokes the function. It reads current state, chooses a branch and updates message. React then displays that message.

Common mistake

onPress={handleLogin()} invokes the function during rendering instead of passing it for later.

Main lesson

Hidden characters do not mean secure login

secureTextEntry

Obscures the displayed characters. It does not encrypt a password or verify an account.

Accessible input

Use meaningful labels. A placeholder disappears when typing, so it is not a persistent visible label.

Layout limitation

A keyboard can cover this minimal centered form. Dismiss it to inspect feedback and record the issue; a production form needs fuller keyboard/layout testing.

Optional ungraded comparison

Optional: clear feedback after a delay

useEffect(() => {
  if (message === "") return;
  const timeoutId = setTimeout(() => setMessage(""), 4000);
  return () => clearTimeout(timeoutId);
}, [message]);

Which timer owns the message?

  • A new message cancels old scheduled work.
  • The new effect schedules its own timeout.
  • The same unchanged message does not restart it.
  • The delay is not a precise clock.

Main lesson

Parang form sa registrar

Analogy

State ang nakasulat sa form. Validation ang guard na tumitingin kung kumpleto. Message ang malinaw na sagot.

Hindi pa ito pag-verify ng identity—kumpletong input lang ang sinusuri.

Troubleshoot

  • Text error: inspect raw text outside Text.
  • Typing fails: inspect value/setter pairing.
  • Error becomes success: inspect early return.
