Main lesson · 1

What is relational database design?

A structured way of organizing data using tables related to one another through keys.

Fields (columns)

Describe the types of data stored, e.g., title, price.

Records (rows)

Individual instances of that data, e.g., “The Great Gatsby”.

Keys

A primary key uniquely identifies a record. A foreign key links to the primary key of another table.

Pro tip: A good relational design minimizes data redundancy (the same data in many places) and maintains data integrity (accurate, consistent data).

Modern update

Diagram-as-Code

From whiteboards to text

Designs were traditionally drawn on whiteboards or in tools like Visio. Modern teams use Diagram-as-Code tools like Mermaid.js, so the ER diagram lives in the project’s documentation (like GitHub) and stays updated alongside the code.

Modern update

Schema migrations and version control

Modern delivery doesn’t “implement” a database once. Schema migration tools (Flyway, Liquibase, Prisma Migrate) treat database changes as code.

Every change is tracked in a Git repository, tested in CI/CD pipelines and deployed automatically to production, ensuring zero downtime.

Analogy

Building construction

Requirements gathering

The client says, “I need a 3-bedroom house with a large kitchen.”

Conceptual design

The architect sketches the rooms and how they connect (ER diagram).

Logical design

The detailed blueprint: exact measurements, door types and electrical layouts (schema definition).

Physical design

Steel beams instead of wood, a specific HVAC system, load-bearing walls (choosing the DBMS, adding indexes).

Implementation

Pouring the concrete and building the walls (executing the SQL).

Real-world use case

A modern e-commerce platform

A modern store doesn’t use one giant relational database.

Relational core

A relational database (e.g., PostgreSQL) handles core transaction data: customers, orders, sales. The design process ensures the schema is optimized for fast transactions.

Document database

The product catalog may use a document (NoSQL) database to handle varying attributes (a shirt has sizes, a laptop has RAM). The design process helps draw the boundary between the relational core and specialized systems.

FAQs

Common questions

Purpose of conceptual design?

A high-level, technology-independent view of the data. It identifies the main entities and relationships, mainly with an ER diagram, so all stakeholders agree on the structure before technical details are decided.

Can AI design a database now?

AI can accelerate the process: ER diagrams from natural language, SQL CREATE TABLE statements, indexing suggestions. Human oversight is still critical for complex business rules, data privacy requirements and long-term scalability.

Logical vs. physical design?

Logical defines data elements, attributes and constraints (primary and foreign keys), independent of any database software. Physical maps that model to a specific DBMS (like MySQL), defining exact data types, indexing strategies and storage structures.

Hands-on exercise

Design a database for an online store

Scenario

A small online clothing store tracks customers, products and sales.
  • Customers: name, address, email.
  • Products: name, description, price, quantity in stock.
  • Sales: product sold, customer, date, quantity, price at the time of sale.

Business rules

1. Products must have a unique name. 2. Prices must be positive. 3. Customers must have a unique email.

Try drawing an ER diagram for this scenario first.

Logical design (SQL)
-- Create the Customers table
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    address TEXT
);

-- Create the Products table
CREATE TABLE Products (
    product_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) CHECK (price > 0),
    quantity_in_stock INT NOT NULL DEFAULT 0
);

-- Create the Sales (Junction) table
-- A customer buys many products and a product is
-- bought by many customers (many-to-many), so we
-- use a Sales table to link them.
CREATE TABLE Sales (
    sale_id INT PRIMARY KEY AUTO_INCREMENT,
    customer_id INT,
    product_id INT,
    sale_date DATE NOT NULL,
    quantity INT NOT NULL,
    sale_price DECIMAL(10, 2) NOT NULL,
    FOREIGN KEY (customer_id)
        REFERENCES Customers(customer_id),
    FOREIGN KEY (product_id)
        REFERENCES Products(product_id)
);

Key quotes

Key definitions to remember

Relational database design

A structured way of organizing data using tables related through keys.

Conceptual design

A high-level, technology-independent view with entities and relationships (ER diagram).

Logical vs. physical

Logical: attributes and constraints, independent of the DBMS. Physical: data types, indexes and storage for a specific DBMS.

Schema migrations

Database changes tracked in Git and deployed through CI/CD.

Recap

A methodical process

Design moves from requirements gathering to conceptual, logical and physical design, then implementation and ongoing maintenance.

A well-designed database ensures data integrity, reduces redundancy and scales efficiently. Schema migrations and Diagram-as-Code let teams manage database changes as safely and rapidly as application code.
