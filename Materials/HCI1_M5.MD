## A. Lesson Preview & Review

Building a strong digital presence—whether on the web or in a mobile app—is crucial for any organization. The way a website looks, feels, and responds makes a massive difference. That is why companies invest heavily in UI and UX designers to enhance the user experience of their applications.

**Why are UX tools so important?**
Imagine trying to explain a complex app idea using just words. It's difficult for clients or team members to visualize. By adopting UX design tools—from initial wireframes to high-fidelity prototypes—teams can confirm they are building the right features early on. This prevents wasted effort, saves costs, minimizes development risks, and ensures you get early feedback from actual end-users.

**Learning Objectives:**
By the end of this module, you should be able to:

## B. Main Lesson

### The Development Stages

Translating an idea into a final product involves several distinct stages:

1.  **Initial Stage: Ideation and Confirmation**
    *   **Wireframing** is highly visual and helps confirm system design ideas with customers. Wireframes are fast, cheap, and easy to change, allowing you to plan the basics before moving forward and avoiding costly rework.
2.  **Detailed Design Stage: Screen Flow Design**
    *   **Storyboards and Wireflows** are used here. A **storyboard** is a structural planning tool used for a single, linear narrative (like a movie). A **wireflow** combines wireframe layouts with a simplified flowchart to show how pages connect and interact.
3.  **Prototype Demonstration Stage: High-Fidelity Design**
    *   **High-Fidelity GUI Design / Prototyping:** A high-fidelity GUI builder allows designers to arrange graphical elements using drag-and-drop editors. A **prototype** is a mid-to-high fidelity representation of the final product that simulates user interface interaction.

---

### What is a Storyboard?

A **storyboard** is a visual depiction of scenes, dialog, and action in a sequential order. It is a method used to mockup ideas and concepts for websites by presenting a sequence of wireframes in a specific order. 

**Why use a storyboard?**
*   It helps UX developers plan user features in a sequential order.
*   It acts as a lightweight, inexpensive way to get early feedback before heavy development begins.
*   It presents an engaging way to show how users will interact with the system.
*   *Note:* Traditionally done in PowerPoint, there are now automated software tools to simplify the process.

#### How to Storyboard a Website Design (7 Steps)

1.  **Collect the information:** Gather all text, images, and content you want on the site.
2.  **Sort the information into topics:** Start broad and work toward the narrowest details.
3.  **Determine the structure of the Web site:** Establish page titles, headings, subheadings, and content.
4.  **Plan how the pages will link:** Decide if the layout will be linear, hierarchical, or a branch design (like a web).
5.  **Layout the menu structure:** Create a logical menu system that will flow across all pages. This prevents you from having to redo menus on multiple pages.
6.  **Layout your template page:** Design the interior page layout that will be consistent across the site.
7.  **Test the layout:** Imagine you are a visitor. Can you enter on any page and navigate easily? If not, start again.

### What are Mockups?

A website **mockup** is a full-size model of a design that demonstrates what the final website will look like. 

*   **Mid-fidelity mockup:** Uses placeholder images and text.
*   **High-fidelity mockup:** Includes a complete visual layout with real colors, typography, and content. 

If you have a wireframe (the structural model), you upgrade it to a mockup by adding color, typography, and other visual features. While people often use the terms sketch, wireframe, mockup, and prototype interchangeably, they represent different stages of fidelity.

#### How to Create a Website Mockup

You can use popular design tools like Figma, InVision, or Sketch to build your mockups. Here are four key things to keep in mind:

1.  **Experiment:** This is the best time to try different colors, fonts, images, and UI elements.
2.  **Style the UI:** Focus on styling navigation bars, buttons, links, sliders, forms, and content containers.
3.  **Mobile-first design:** Start by putting only necessary elements on a mobile screen, then scale up to tablet and desktop dimensions. This ensures the core functionality is prioritized.
4.  **Avoid Dummy Text:** Do not use "Lorem Ipsum." While it seems like a time-saver, neglecting real content at this stage can prolong workflow and result in unsatisfying layouts.

## C. Analogies and Use Cases

### The Movie Production Analogy
Think of creating a website like making a movie:
*   **Sketches:** The director's scribbled notes on a napkin.
*   **Wireframes:** The blueprint of the set.
*   **Storyboards:** The comic-strip version of the script showing scene-by-scene what the actors will do.
*   **Mockups:** The actual set design, complete with lighting and props, ready to be filmed.

### Use Case: The E-Commerce Checkout
When designing an online flower shop:
1.  **Wireflow:** You map out the path from "Product Page" -> "Cart" -> "Shipping Info" -> "Payment" -> "Confirmation".
2.  **Storyboard:** You create a sequence showing exactly what the user sees on screen as they move through those steps.
3.  **Mockup:** You apply the brand's colors (e.g., pastel pinks and greens), add high-quality photos of the bouquets, and use real text for the "Order Now" buttons.

## D. Lesson Wrap-Up / FAQs

### Key Takeaways
*   **Storyboards** focus on the *narrative* and *sequence* of user interactions across multiple pages.
*   **Wireflows** combine structural wireframes with flowcharts.
*   **Mockups** are full-size, visually complete representations of the final design (mid-to-high fidelity).
*   Good mockups use real content (no Lorem Ipsum) and are designed **mobile-first**.
*   Always test your flow from the perspective of a user before moving to development.

### Quick Comparison Guide

| Term | Focus | Fidelity | Purpose |
| :--- | :--- | :--- | :--- |
| **Sketch** | Quick ideation | Very Low | Brainstorming, disposable ideas. |
| **Wireframe** | Structure & Layout | Low | Outlining page elements without colors/images. |
| **Storyboard** | User Journey & Sequence | Low/Mid | Showing how pages flow together in a narrative. |
| **Mockup** | Visual Design | Mid/High | Showing exactly what the final UI will look like. |

### Frequently Asked Questions

**Q: What is the difference between a wireframe and a mockup?**
**A:** A wireframe is a basic structural outline (like a blueprint) that shows where elements go. A mockup is a high-fidelity visual representation that includes colors, typography, and actual images to show what it will really look like.

**Q: Why is it bad to use Lorem Ipsum dummy text in a mockup?**
**A:** Lorem Ipsum doesn't account for real-world text lengths or tone. Using it can create false layouts that break when actual content (which might be longer or shorter) is added later. It also prevents stakeholders from accurately evaluating the user experience.
