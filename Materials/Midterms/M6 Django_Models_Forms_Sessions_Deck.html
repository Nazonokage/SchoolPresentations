00_intro.py

Why This Matters

Three problems every real app runs into, in order.

1. Where does data live?

Variables inside a view vanish the moment the request ends. You need something permanent — a database, defined by models.py.

2. Can you trust user input?

Never. Forms validate it, and CSRF protection stops attackers from submitting on a user's behalf.

3. Who is this visitor?

HTTP forgets everyone between requests. Sessions are how a server remembers "this is the same person as before."

04_models_deep_dive.py

        
Models.py Deep Dive

        
A model is a Python class that Django turns into a database table — one class, one table, one row per instance.

        

          

            
Field types you'll use constantly

            
    
              
  • CharField — short text, requires max_length
    • 
              
  • TextField — long text, no length limit
    • 
              
  • BooleanField — True/False
    • 
              
  • IntegerField — whole numbers
    • 
              
  • DateTimeField — timestamps, often with auto_now_add=True
    • 
              
  • ForeignKey — links to another model (a relationship)
    • 
            

          

          

            
The two-step deploy

            
    
              
  1. makemigrations — Django reads your model changes and writes a migration file describing them.
    2. 
              
  2. migrate — Django actually applies that file, creating or altering the real database table.
    3. 
            

            
Change a model without running both, and the database quietly falls out of sync with your code.

06_forms_csrf.py

        
Forms & CSRF — Never Trust the Client

        

          

            
Why not just read request.POST directly?

            
    
              
  • Nothing stops a user from submitting empty, malformed, or malicious data
    • 
              
  • forms.Form centralizes validation rules in one place, not scattered across views
    • 
              
  • Client-side (JS) validation is a UX nicety — it can always be bypassed. Server-side is the real gate
    • 
            

          

          

            
What is CSRF, really?

            
Cross-Site Request Forgery: a malicious site tricks a logged-in user's browser into submitting a form to your site without them knowing.

            
{% csrf_token %} embeds a secret, per-session token. Django rejects any POST that doesn't include the matching token — a foreign site can't guess it.

          

        

      

    


    
    

      

        
07_forms_code.py

        
Code Breakdown — forms.Form in Action

        

          

            
python + template

            

          

          

            
forms.Form Declares each field once — Django generates matching HTML inputs and validation rules automatically.

            
form.is_valid() Runs every field's validation. Returns False if anything's missing or malformed.

            
form.cleaned_data A dict of the validated, type-converted values — never read raw request.POST after this exists.

            
{{ form.as_p }} Renders every field as a <p>-wrapped input — errors included automatically on re-render.

            
{% csrf_token %} Non-negotiable inside every method="post" form.

11_sessions.py

        
Sessions — Remembering One Visitor

        

          

            
😩 The problem with a plain global variable

            
    
              
  • A variable set in a view is shared by every single visitor, not just one
    • 
              
  • User A's cart, login state, or progress would leak straight into User B's request
    • 
              
  • HTTP itself has no memory — each request is a stranger to the last
    • 
            

          

          

            
✅ request.session fixes it

            
    
              
  • Acts like a dictionary — but scoped to one visitor's browser via a cookie
    • 
              
  • Data set in one request is still there on their next request
    • 
              
  • Backed by a real database table — created the moment you run migrate
    •

12_sessions_code.py

        
Code Breakdown — request.session

        

          

            
python

            

          

          

            
.get("visits", 0) Reads the key if it exists, otherwise falls back to 0 — safe on a brand-new session.

            
request.session["visits"] = visits Writing to the session is just dictionary assignment — Django handles the cookie and storage.

            
Per-visitor, not global Two different browsers get two completely separate counters.

            
Initialization check Always use .get(key, default) the first time — a key that's never been set will otherwise raise an error.

15_why_we_do_this.py

        
Why We Bother With Any of This

        

          
Data integrity
Models + migrations keep your database structure and your Python code from silently drifting apart.

          
Security by default
Forms + CSRF mean "trust nothing from the client" is the default, not something you have to remember every time.

          
Personalized state
Sessions are what let a stateless protocol (HTTP) feel like a stateful app — carts, logins, preferences that persist.

        

        

          
The bigger picture

          
Every serious framework — Express, Rails, Laravel — solves these exact three problems the same way: a model layer, validated input, and session storage. Learn the pattern here, and it transfers directly.

recap.py

        
Recap Before You Go

        
The essentials worth remembering.

        

          
✓A model = one Python class = one database table. makemigrations writes the plan, migrate applies it.

          
✓Never trust request.POST directly — always validate through a form first.

          
✓is_valid() must return True before cleaned_data (or save()) can be trusted.

          
✓{% csrf_token %} is non-negotiable in every POST form — no exceptions.

          
✓ModelForm removes the duplication between a model's fields and a form's fields.

          
✓request.session is per-visitor memory — a global variable is not.
