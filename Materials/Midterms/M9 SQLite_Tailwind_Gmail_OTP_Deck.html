01_sqlite_intro.py

SQLite — The Database Hiding in Plain Sight

What it actually is

  • A full relational database that lives inside one single file — db.sqlite3
  • No separate server process to install, start, or stop
  • Ships with Python itself — nothing extra to install

Why Django defaults to it

  • Zero configuration — startproject is ready to migrate immediately
  • Perfect for learning, prototypes, and small single-user apps
  • The exact same ORM code works if you switch databases later

Analogy

Like a spreadsheet file you can query with real SQL — no server to boot up, just a file sitting in your project folder.

03_sqlite_when_to_switch.py

        
When to Outgrow SQLite

        

          

            
Stick with SQLite when

            
    
              
  • You're learning, prototyping, or building a small single-user tool
    • 
              
  • Traffic is light — one or two people writing data at a time
    • 
              
  • You want zero deployment complexity
    • 
            

          

          

            
Switch to MySQL/Postgres when

            
    
              
  • Many users write data at the same time — SQLite locks the whole file per write
    • 
              
  • You need the database running on its own server, separate from the app
    • 
              
  • You're heading toward real production traffic
    • 
            

          

        

        

          
The good news

          
Switching only ever touches settings.py's DATABASES block. Every model and every view stays exactly the same — that's the entire point of Django's ORM.

        

      

    


    
    

      

        
04_tailwind_intro.py

        
Tailwind CSS — If You've Used Bootstrap, You Already Get This

        
Same goal — styled pages fast, without hand-writing CSS. Different philosophy underneath.

        

          

            
Bootstrap's approach

            
    
              
  • Pre-built components: .btn, .card, .container
    • 
              
  • You memorize component class names, then get the look for free
    • 
              
  • Customizing beyond the default look usually means overriding Bootstrap's own CSS
    • 
            

          

          

            
Tailwind's approach

            
    
              
  • Utility-first — every class does exactly one thing
    • 
              
  • bg-white p-4 rounded-lg — background, padding, corner radius, composed directly in the HTML
    • 
              
  • No component names to memorize — the classes describe exactly what they do
    •

The Bootstrap-to-Tailwind Dictionary

        
You already know what these do. Here's the Tailwind spelling.

.card→bg-white shadow rounded-lg p-6

          
.container→max-w-7xl mx-auto px-4

          
.d-flex .justify-content-between→flex justify-between

          
.text-center→text-center (some names are just... the same)

08_otp_intro.py

        
Gmail OTP — Proving an Email Is Real

        

          

            
😩 Without verification

            
    
              
  • Anyone can type any email address into a form — yours, a stranger's, a fake one
    • 
              
  • Nothing confirms the person submitting it can actually read that inbox
    • 
            

          

          

            
✅ One-Time Password (OTP)

            
    
              
  • A short-lived code, emailed to the address they typed
    • 
              
  • Only someone who can open that inbox can type the code back correctly
    • 
              
  • Same idea as the "enter the code we texted you" flow on almost every app
    • 
            

          

        

        

          
        

      

    


    
    

      

        
08a_google_app_password.py

        
Setting Up Google: Generating Your App Password

        
A one-time walkthrough inside your Google Account — no code yet, just clicks.

        

          
1
In Gmail, click your profile icon (top right) → Manage your Google Account.

          
2
Turn on 2-Step Verification first if you haven't — App Passwords stay hidden in the menu until it's enabled.

          
3
Type "App Passwords" into the account's search bar and open it — the exact menu location moves around, so searching is the fastest way in.

          
4
Re-enter your regular Google password when asked, to confirm it's really you.

          
5
Give the app a name you'll recognize later — e.g. "Django OTP App" — and click Create.

          
6
Google shows a 16-character password once — copy it immediately, then click Done.

          
7
Paste it into your project as EMAIL_HOST_PASSWORD, removing any spaces Google inserted for readability. Never your regular Gmail password here — it will always be rejected.

        

      

    


    
    

      

        
09_otp_setup_guide.py

        
Setup Guide — Gmail SMTP

        
Gmail won't accept your normal password for this — one extra step first.

        

          

            
settings.py

            

          

          

            
App Password Enable 2-Step Verification on the Gmail account first, then generate a 16-character App Password — Google blocks plain-password SMTP logins entirely.

            
EMAIL_HOST_PASSWORD Never commit this directly — real projects load it from an environment variable or a .env file.

            
EMAIL_USE_TLS Encrypts the connection to Gmail's SMTP server — required, not optional.

Recap Before You Go

        
The essentials worth remembering.

        

          
✓SQLite is a whole database in one file — db.sqlite3 — with zero server to run.

          
✓Switching databases later only touches settings.py — models and views stay untouched.

          
✓Tailwind styles directly in HTML with utility classes — no separate stylesheet growing forever.

          
✓The CDN is for learning and demos; a real build step is for production.

          
✓Gmail SMTP needs an App Password — your regular password will be rejected.

          
✓An OTP proves inbox ownership — store it in the session, never a global variable.
