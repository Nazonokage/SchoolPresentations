Linked Lists:
"Who's Next?"

Every node only needs to know one thing: what comes after it. That one idea builds three structures — and one of them, Java already built for you.

java.util.LinkedList Singly Linked List Doubly Linked List
ROADMAP

How we'll build this up

Six stops, each one explaining why the next stop exists.

We'll finish exactly where we start: java.util.LinkedList — except now it won't feel like magic Java syntax.

THE PROBLEM

Why not just use an ArrayList?

ArrayList — a row of fixed seats

Items sit in one continuous block of memory, back to back like numbered seats in a row.

  • Fast to jump to any seat by number
  • Insert in the middle? Every seat after it has to shift over

LinkedList — a line of people holding hands

Each person just needs to grab a new hand. Nobody else in the line has to move.

  • Insert / remove anywhere is cheap — just re-point a hand
  • Want seat #47? You have to walk the line to count to it

That trade-off — fast jumps vs. cheap inserts — is the whole reason linked lists exist.

01
PART ONE

java.util.LinkedList

The one Java already built for you.

SAMPLE 1 · BUILT-IN

IRL analogy: a To-Do list app

Main.java
import java.util.LinkedList;

public class Main {
    public static void main(String[] args) {

        LinkedList<String> tasks = new LinkedList<>();

        tasks.add("Reply to emails");
        tasks.add("Review pull request");
        tasks.add("Write report");

        System.out.println("Tasks:");
        System.out.println(tasks);

        // Urgent task jumps to the front
        tasks.addFirst("Fix production bug");

        // New task goes to the back
        tasks.addLast("Plan next sprint");

        System.out.println("\nUpdated tasks:");
        System.out.println(tasks);

        tasks.remove("Review pull request");

        System.out.println("\nAfter removing a task:");
        System.out.println(tasks);
    }
}

Each task is a node. It doesn't know the whole list — only which task comes after it.

addFirst and addLast don't shift anything — they just attach a node at either end.

java.util.LinkedList is Java's ready-made implementation — you never have to write the node-connecting code yourself.

02
PART TWO

Singly Linked List

Build it yourself — one arrow at a time.

SAMPLE 2 · BUILD IT YOURSELF

IRL analogy: a store queue

Each person in line only needs to know who's next. Not the whole line — just the one hand in front of them.

holds data points to next last person → null
Node.java
class Node {
    String name;
    Node next;

    Node(String name) {
        this.name = name;
        this.next = null;
    }
}
SINGLY LINKED LIST

Connecting three people

Main.java
public class Main {
    public static void main(String[] args) {

        Node person1 = new Node("Josh");
        Node person2 = new Node("Mark");
        Node person3 = new Node("John");

        // Connect the people
        person1.next = person2;
        person2.next = person3;

        // Start at the first person
        Node current = person1;

        while (current != null) {
            System.out.println(current.name);
            current = current.next;
        }
    }
}

Output:

Josh
Mark
John

The node knows: "here's my data, and here's the next node." It has no idea who came before it — that's the missing piece Part 3 adds.

RECAP · SINGLY

Anatomy of a singly-linked node

What it has: its own data, and one arrow forward.

What it's missing: any way to look backward. To go back, you'd have to restart from the head.

03
PART THREE

Doubly Linked List

Now the node can look both ways.

SAMPLE 3 · TWO-WAY

IRL analogy: a photo gallery viewer

Swiping a gallery, you can go Next or Previous. The current photo needs to know both neighbors.

Node.java
class Node {
    String photo;
    Node next;
    Node previous;

    Node(String photo) {
        this.photo = photo;
        this.next = null;
        this.previous = null;
    }
}
DOUBLY LINKED LIST

Walking forward, then back

Main.java
public class Main {
    public static void main(String[] args) {

        Node photo1 = new Node("Beach.jpg");
        Node photo2 = new Node("Mountain.jpg");
        Node photo3 = new Node("City.jpg");

        // Forward connections
        photo1.next = photo2;
        photo2.next = photo3;

        // Backward connections
        photo2.previous = photo1;
        photo3.previous = photo2;

        Node current = photo1;
        System.out.println("Forward:");
        while (current != null) {
            System.out.println(current.photo);
            current = current.next;
        }

        current = photo3;
        System.out.println("\nBackward:");
        while (current != null) {
            System.out.println(current.photo);
            current = current.previous;
        }
    }
}

Output:

Forward:
Beach.jpg
Mountain.jpg
City.jpg

Backward:
City.jpg
Mountain.jpg
Beach.jpg

Same three nodes, walked in both directions — because each one carries a previous reference, not just next.

COMPARE

Singly vs. Doubly

Singly

  • Node fields: next
  • One direction only
  • Slightly less memory per node

Doubly

  • Node fields: next + previous
  • Walk forward or backward
  • This is what java.util.LinkedList actually is under the hood

REAL-LIFE SCENARIOS

Where you've already used one

To-Do apps

Reordering, pinning to top, checking off — each task is a node.

Any queue / line

Ticket counters, call centers, print jobs — first in, first handled.

Gallery / media viewers

Next / Previous photo, undo/redo history — needs both directions.

RECAP

Before we code: the short version

  • Node = one unit of data + a reference to the next node (and, for doubly, the previous one too).
  • Singly linked list — walk forward only; cheap to insert/remove, no backward view.
  • Doubly linked list — walk either direction; costs one extra reference per node.
  • java.util.LinkedList — Java's doubly linked list, ready to use, no manual node-wiring needed.

Your task: Grace just arrived and wants to stand right behind Mark. Finish insertAfter so the output is Josh, Mark, Grace, John.

  • Hint 1: Before you rewrite anything, save target.next in a temporary variable — that's the rest of the line, don't lose it.
  • Hint 2: The new node's next should point to whatever you just saved.
  • Hint 3: Then, and only then, set target.next to point to the new node.

SAMPLE SOLUTION

One way to solve it

insertAfter() — solved
static void insertAfter(Node target, String newName) {
    Node newNode = new Node(newName);
    newNode.next = target.next;
    target.next = newNode;
}

Three lines, in this exact order matters: save first, point the new node forward, then rewire the target — otherwise you overwrite the only reference to the rest of the line.

Part B, worked example — elevator floors:

Doubly — because the elevator goes up and comes back down. That "does it ever reverse?" question is the whole test for singly vs. doubly.
