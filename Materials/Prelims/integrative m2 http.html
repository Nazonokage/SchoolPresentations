HTTP: The Protocol Behind Every Web Request

Before Django can do anything, every click, load, and submit on the web speaks one shared language. Let's decode it — request methods and status codes.

01 · The Big Idea

What Is HTTP, Really?

HTTP = HyperText Transfer Protocol — the agreed-upon set of rules for how messages travel back and forth over the internet.

  • A client (your web browser) sends a request.
  • A server (our Django app) processes it and sends back a response.
  • This request → response cycle is the heartbeat of the entire web.
CLIENT SENDS →
GET /page HTTP/1.1
Host: example.com
← SERVER RESPONDS
HTTP/1.1 200 OK
Content-Type: text/html
02 · Request Methods

GET vs. POST

A request method tells the server what kind of action you're asking it to perform.

RETRIEVE
GET
"I would like to get a particular page." Used any time you type a URL and hit Enter, or click a link. No state is changed on the server — you're just asking to view something.
→ typing example.com/hello
SUBMIT
POST
Used to submit data that has the potential to change something — like adding a new task. Data travels in the body of the request, not exposed in the URL.
→ submitting an "Add Task" form
03 · Status Codes

The Server Always Replies With a Code

Every single response starts with a 3-digit status code — a quick signal for what happened to your request.

2xxSuccess
3xxRedirection
4xxClient Error
5xxServer Error

Think of it like a quick verbal reply: "got it, here you go", "look over there instead", "you asked for something wrong", or "I messed up on my end."

03 · Status Codes

The 5 You'll See Constantly

200
OK
Everything worked. Page returned successfully.
301
Moved Permanently
You're redirected from one URL to another.
404
Not Found
The page you requested doesn't exist.
403
Forbidden
You're not permitted to access this page.
500
Server Error
Something's buggy on the server's own code.

💡 Later on, submitting a form without a CSRF token will trigger a real 403 Forbidden — you'll meet this one again.
