Step 1 · Installation

Installing Django

  • Django is just a Python package — installed the same way as any other, using pip, Python's package manager.
  • We use pip3 specifically because we're working in Python 3.
  • Once installed, Django gives us new command-line tools — most importantly django-admin.
TERMINAL
$ pip3 install Django Collecting Django... Successfully installed Django-5.x
🔧
Real-life analogy
Think of pip3 as a hardware store and Django as a power tool on the shelf. You don't build the drill yourself — you just "buy" it (pip3 install Django) and it's ready to use in your toolbox.
Step 2 · Scaffolding

Creating the Project

TERMINAL
$ django-admin startproject lecture3 $ ls lecture3/
  • django-admin startproject [name] generates an entire starter folder for you — you write zero of these files by hand.
  • The name (lecture3 here) can be anything — it becomes your project's root folder.
  • This single command is the entire "birth" of a Django project. Everything else builds on top of it.
🏠
Real-life analogy
Like ordering a furnished starter apartment instead of building a house from raw lumber — the walls, plumbing, and wiring (files & folders) are already there. You just move in and start decorating.
Step 3 · Anatomy

What Django Just Handed You

Three files matter most right now — and a few quieter ones sit alongside them.

Command Executor
manage.py
The tool you'll run every command through — python manage.py [command]. You'll rarely edit it, only run it.
Configuration
settings.py
Every important setting for your app lives here — installed apps, database config, security settings, and more. Comes preloaded with sane defaults.
Routing
urls.py
Think of it as the "table of contents" for your site — every visitable route on your web app is registered somewhere in here.
Package Marker
__init__.py
Tells Python this folder is a package. You'll almost never open it.
Deployment
wsgi.py
The entry point production web servers use to talk to your Django app.
Deployment (async)
asgi.py
Same idea as wsgi.py, but for asynchronous servers. Not a concern yet.
🏢
Real-life analogy
Picture a small office: manage.py is the front-desk phone you use to give commands, settings.py is the office manual with all the rules, and urls.py is the receptionist's directory that sends each visitor to the right room.

Step 3.5 · Read The Code · Part 2

The File That Runs Everything

manage.pyThe entry point every command runs through
import os
import sys

def main():
    os.environ.setdefault("DJANGO_SETTINGS_MODULE", "lecture3.settings")
    from django.core.management import execute_from_command_line
    execute_from_command_line(sys.argv)

if __name__ == "__main__":
    main()
📺
Real-life analogy
manage.py works like a TV remote: you never rewire the television itself, you just press a button (a command) and the remote tells the TV what to do.
Sample use case
Say you want to check whether your app registered new database changes. Instead of digging through Django's internals, you just run python manage.py migrate — one command, routed through manage.py, that does the heavy lifting for you.
Step 4 · Liftoff

Running the Development Server

TERMINAL
$ python manage.py runserver Starting development server at http://127.0.0.1:8000
  • manage.py always takes a command as its argument — here, runserver means "start the web server."
  • 127.0.0.1 is your own computer's local address — only you can reach this server, nobody else on the internet.
  • 8000 is the port number — it identifies which service is running, since a computer can host many at once.
🏢
Real-life analogy
127.0.0.1 is like a private rehearsal room only you hold the key to. The 8000 is the room number in the building — the address gets you inside, the number picks the exact room.
Putting It Together

Sample Use Case: Building a Portfolio Site

A concrete walkthrough tying every command and file from this lecture into one real task.

1
pip3 install Django
You want a personal portfolio site. First, "buy the tool" — install Django into your Python environment.
2
django-admin startproject portfolio
Scaffold the whole project. You now have a furnished starter folder called portfolio.
3
Edit urls.py
Add a route so visiting "/" shows your homepage — like telling the receptionist where to send guests.
4
python manage.py runserver
Press the remote-control button to switch the server on and preview your site at 127.0.0.1:8000.
Why this matters
Every Django project you'll ever build — a blog, a shop, a portfolio — starts with this exact same four-step rhythm: install, scaffold, configure routes, run. Once this feels automatic, everything later in the course builds on it.

Python's in operator checks list membership in one step — no manual loop needed.
04Plain Python: Build a Route Matcher
def match_route(route):
    for p in urlpatterns:
        if p["route"] == route:
            return p["view"]
    return None
Loop through each dict, compare the "route" key, and return its "view" on a match. If the loop finishes with no match, fall through to None.
