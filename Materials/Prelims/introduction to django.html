Model: The Data Blueprint

Python classes that map to database tables. Defines fields, relationships, and validation.

from django.db import models class User(models.Model): username = models.CharField(max_length=100) email = models.EmailField(unique=True) date_joined = models.DateTimeField(auto_now_add=True) def __str__(self): return self.username
purpose
Define data structure & relationships
orm
Query data with Python, not SQL
migrations
Auto-generated schema changes

URL Dispatcher: The Receptionist

Maps URL patterns to views — the entry point for all requests.

from django.urls import path from . import views urlpatterns = [ path('', views.home, name='home'), path('profile/<int:user_id>/', views.profile, name='profile'), path('about/', views.about, name='about'), ]
route
String pattern → view mapping
parameters
<int:id> · <str:slug> · <uuid:uid>
reverse
{% url 'name' arg %} · reverse('name')

django_intro.pyproject_vs_app.py
modular blueprint
Project vs. App
🏢 project
The whole complex
Management, shared infrastructure, global settings.
django-admin startproject
Contains: settings, root URLs, WSGI/ASGI, manage.py
🚪 app
Individual apartment unit
Self-contained, reusable, plug-and-play.
python manage.py startapp
Contains: models, views, templates, admin, migrations
💡 A single Project can contain many Apps — that's the "plug-and-play" modularity.

quiz.pyanswers_1_5.py
quiz — answers 1–5
Answers 1–5
A1. B) MVT — Model-View-Template. Django's pattern separates data, logic, and presentation.
A2. Project = entire website (settings, URLs, config). App = self-contained feature (models, views, templates). Project is the complex, app is one apartment unit.
A3. C) URL Dispatcher — defined in urls.py, it acts like a receptionist directing requests to views.
A4. C) django-admin startproject mywebsite . — the dot creates it in the current directory without nesting.
A5. Isolates dependencies — different projects can use different package versions without conflicts. Like separate toolboxes for each job.
quiz.pyanswers_6_10.py
quiz — answers 6–10
Answers 6–10
A6. Applies database migrations — creates tables and schema changes from models. It builds tables like auth_user and django_session.
A7. settings.py — in the INSTALLED_APPS list. This "plugs" the app into the project.
A8. Model (data structure) · View (logic/processing) · Template (presentation/HTML).
A9. Restricts access — only authenticated users can view the decorated view. Unauthenticated users are redirected to the login page.
A10. startproject creates the whole project (settings, URLs). startapp creates a self-contained feature module inside the project.
