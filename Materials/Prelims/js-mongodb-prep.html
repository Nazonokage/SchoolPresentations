Runtime · 00

What is Node.js?

JavaScript was built to run inside a browser. Node.js takes the same engine that powers Chrome (V8) and lets JavaScript run anywhere — your laptop, a server, a script you trigger from the terminal. That's what makes JS-powered backends, and eventually a JS app that talks to MongoDB, possible.

JavaScript — Node.js
// app.js
console.log("Hello from Node.js!");
console.log(typeof window);
$ node app.js
›Hello from Node.js!
›undefined — no browser here
Python
# app.py
print("Hello from Python!")
import sys
print(sys.platform)
$ python app.py
›Hello from Python!
›linux (or "darwin" / "win32")
npm ↔ pip (packages)
package.json ↔ requirements.txt
node app.js ↔ python app.py
Why this matters for MongoDB

Node.js and MongoDB are a classic pair (the "N" and "M" in the MEAN/MERN stack) because they both think in the same shape: JSON-like objects. Everything you learn in this deck — variables, arrays, objects — is what you'll use to write a Node.js server that reads and writes MongoDB documents.

JS Basics · 01

let, var, const

These are three ways to create a "box" that holds a value. The difference is where the box can be used and whether you can put a new value in it later.

let

Block-scoped. Value can change. Default choice.

var

Function-scoped, ignores blocks. Legacy — avoid.

const

Block-scoped. Cannot be reassigned.

JavaScript
let name = "Juan";
const age = 20;
var oldStyle = "avoid";

name = "Maria";   // OK
// age = 21;   // Error: constant

console.log(name, age);
›Maria 20
Python
name = "Juan"
age = 20
AGE_LIMIT = 20  # ALL_CAPS = "treat as constant"

name = "Maria"  # fine, Python has no let/const

print(name, age)
›Maria 20
Python has no let/var/const — every name is reassignable. "Constants" are just a naming convention, not enforced by the language.
Use case

In a student record app, a grade changes every exam, but a student ID should never change once created. This same idea carries into MongoDB: fields you update often vs. fields that identify a document.

JS Basics · 02

Checking data types

Every value has a type. Knowing it matters when data arrives from a form, a file, or a database and you're not 100% sure what shape it's in.

JavaScript — typeof
console.log(typeof "hello");
console.log(typeof 42);
console.log(typeof true);
console.log(typeof {name: "Juan"});
console.log(typeof [1,2,3]);
console.log(typeof (() => {}));
console.log(typeof undefined);
›"string"
›"number"
›"boolean"
›"object"
›"object" (arrays too)
›"function"
›"undefined"
Python — type()
print(type("hello"))
print(type(42))
print(type(True))
print(type({"name": "Juan"}))
print(type([1,2,3]))
print(type(lambda: None))
print(type(None))
›<class 'str'>
›<class 'int'>
›<class 'bool'>
›<class 'dict'>
›<class 'list'>
›<class 'function'>
›<class 'NoneType'>
Python has no undefined — None is the closest equivalent.
Use case

Before saving user input to a database, you confirm the age field is really a number, not text someone typed by mistake. In both languages, arrays/lists share a broader type ("object" / list is its own type) — that's why JS has Array.isArray() and Python has isinstance(x, list) for a precise check.

JS Basics · 03

Conditionals

JavaScript — if / switch
let age = 15;
if (age >= 18) console.log("Adult");
else if (age >= 13) console.log("Teen");
else console.log("Child");

let course = "BSCS";
switch(course) {
  case "BSIT": console.log("IT"); break;
  case "BSCS": console.log("CS"); break;
  default: console.log("Other");
}
›Teen
›CS
Python — if / match
age = 15
if age >= 18: print("Adult")
elif age >= 13: print("Teen")
else: print("Child")

course = "BSCS"
match course:
    case "BSIT": print("IT")
    case "BSCS": print("CS")
    case _: print("Other")
›Teen
›CS
match/case (Python 3.10+) is the closest thing Python has to switch.
Use case

A grading system decides pass/fail, a cart decides on free shipping. Later, MongoDB queries use this same "if it matches, include it" logic through operators like $gte and $eq.

JS Basics · 04

Loops

A loop repeats code so you don't write it by hand for every item. Pick the loop based on what you're repeating over.

JavaScript
for (let i = 0; i < 3; i++) {
  console.log("Round", i);
}

let subjects = ["DSA", "Web Dev"];
for (let sub of subjects) console.log(sub);

let student = { name: "Juan", age: 20 };
for (let key in student) {
  console.log(key, "→", student[key]);
}
›Round 0 / Round 1 / Round 2
›DSA / Web Dev
›name → Juan / age → 20
Python
for i in range(3):
    print("Round", i)

subjects = ["DSA", "Web Dev"]
for sub in subjects: print(sub)

student = {"name": "Juan", "age": 20}
for key in student:
    print(key, "→", student[key])
›Round 0 / Round 1 / Round 2
›DSA / Web Dev
›name → Juan / age → 20
A plain Python for x in list already does what JS needs for...of for — Python doesn't separate the two cases.
Use case

Rendering every student on a page, or averaging class grades — both loops. A MongoDB query result is a list of documents, and you'll loop over it exactly like the examples above.

JS Basics · 05

Functions

A function packages logic so you can name it, reuse it, and hand it inputs.

JavaScript — function / arrow
function add(a, b) {
  return a + b;
}
console.log(add(2, 3));

const add2 = (a, b) => a + b;
console.log(add2(2, 3));
›5
›5
Python — def / lambda
def add(a, b):
    return a + b
print(add(2, 3))

add2 = lambda a, b: a + b
print(add2(2, 3))
›5
›5
JS arrow functions ↔ Python lambda — both are short, throwaway function syntax.
Use case

A calculateAverage(grades) function keeps grade math in one place. Short functions like this are exactly what you pass into MongoDB driver methods like .find() or Python's .map()-style comprehensions.

Arrays · 06

Arrays — ordered lists of values

A single variable holding many values in order, each reachable by index, starting at 0.

JavaScript — Array
let subjects = ["DSA", "Web Dev", "Math"];
console.log(subjects[0]);
console.log(subjects.length);

subjects.push("Networking");
subjects.pop();
console.log(subjects);

let shout = subjects.map(s => s.toUpperCase());
console.log(shout);

let filtered = subjects.filter(s => s.length > 4);
console.log(filtered);
›DSA
›3
›["DSA", "Web Dev", "Math"]
›["DSA", "WEB DEV", "MATH"]
›["Web Dev", "Math"]
Python — list
subjects = ["DSA", "Web Dev", "Math"]
print(subjects[0])
print(len(subjects))

subjects.append("Networking")
subjects.pop()
print(subjects)

shout = [s.upper() for s in subjects]
print(shout)

filtered = [s for s in subjects if len(s) > 4]
print(filtered)
›DSA
›3
›['DSA', 'Web Dev', 'Math']
›['DSA', 'WEB DEV', 'MATH']
›['Web Dev', 'Math']
JS .map()/.filter() ↔ Python list comprehensions — same idea, different syntax.
Use case

A cart's items, a playlist's songs, a student's enrolled subjects. MongoDB stores lists inside a document the same way: subjects: ["DSA", "Web Dev"] is a real, valid field.

Arrays · 07

Multi-dimensional arrays

An array whose items are themselves arrays — a grid instead of a line. Like a spreadsheet: the outer array is rows, each inner array is one row's columns.

JavaScript
// [ name, grade, course ]
let students = [
  ["Juan",  85, "BSIT"],
  ["Maria", 92, "BSCS"]
];
console.log(students[0][0]);  // row, column

for (let row of students) {
  for (let cell of row) console.log(cell);
  console.log("---");
}
›Juan
›Juan / 85 / BSIT / ---
›Maria / 92 / BSCS / ---
Python
# [ name, grade, course ]
students = [
    ["Juan",  85, "BSIT"],
    ["Maria", 92, "BSCS"]
]
print(students[0][0])  # row, column

for row in students:
    for cell in row:
        print(cell)
    print("---")
›Juan
›Juan / 85 / BSIT / ---
›Maria / 92 / BSCS / ---
Use case

Grid-shaped data: a seating chart, a tic-tac-toe board, pixel rows in an image. This is the stepping stone to MongoDB, where a field is more often an array of objects than an array of arrays — next slide.

Objects · 08

Objects — labeled data

Where an array uses position ([0]), an object uses a named key. Use one when each piece of data has a role, not just a place in line.

JavaScript — object
let student = {
  name: "Juan",
  age: 20,
  address: { city: "Manila" },
  subjects: ["DSA", "Web Dev"]
};
console.log(student.name);          // dot notation
console.log(student["age"]);       // bracket notation
console.log(student.address.city);
console.log(student.subjects[1]);
›Juan
›20
›Manila
›Web Dev
Python — dict
student = {
    "name": "Juan",
    "age": 20,
    "address": {"city": "Manila"},
    "subjects": ["DSA", "Web Dev"]
}
print(student["name"])         # bracket only
print(student["age"])
print(student["address"]["city"])
print(student["subjects"][1])
›Juan
›20
›Manila
›Web Dev
Python dicts have no dot notation — always student["name"], never student.name.
Use case

A user profile, a product listing, an API response — real data almost always has named fields. This is exactly what a MongoDB document looks like.

Bridge to MongoDB · 09

Arrays of objects

A list of student records, but each row is a labeled object instead of a position-based row. This is the exact shape of a MongoDB collection.

JavaScript
let students = [
  { name: "Juan",  grade: 85, course: "BSIT" },
  { name: "Maria", grade: 92, course: "BSCS" }
];
for (let s of students) console.log(s.name, "-", s.grade);

let names = students.map(s => s.name);
console.log(names);
›Juan - 85
›Maria - 92
›["Juan", "Maria"]
Python
students = [
    {"name": "Juan",  "grade": 85, "course": "BSIT"},
    {"name": "Maria", "grade": 92, "course": "BSCS"}
]
for s in students:
    print(s["name"], "-", s["grade"])

names = [s["name"] for s in students]
print(names)
›Juan - 85
›Maria - 92
›['Juan', 'Maria']
Why this matters for MongoDB

A MongoDB collection of documents is just this pattern: an array of objects (or in Python driver code, a list of dicts). When you later run db.students.find(), what comes back is exactly this shape.

Data Exchange · 10

JSON conversion

JSON is text that represents an object or array. Databases, APIs, and files all speak it, so you constantly convert between "live" data and JSON text.

JavaScript — JSON
let student = { name: "Juan", age: 20 };

let asText = JSON.stringify(student);
console.log(asText);
console.log(typeof asText);

let back = JSON.parse(asText);
console.log(back.name);
›{"name":"Juan","age":20}
›"string"
›Juan
Python — json module
import json
student = {"name": "Juan", "age": 20}

as_text = json.dumps(student)
print(as_text)
print(type(as_text))

back = json.loads(as_text)
print(back["name"])
›{"name": "Juan", "age": 20}
›<class 'str'>
›Juan
JS JSON.stringify/parse ↔ Python json.dumps/loads.
Use case

MongoDB documents are stored as BSON, a binary cousin of JSON — this is the format you'll be reading and writing constantly, whether your backend is Node.js or Python.

Answers — Technical Quiz & Grade Calculator

Technical Quiz Answers

Grade Calculator — Sample Solution
const students = [
  { name: "Juan",  grades: [85,90,78] },
  { name: "Maria", grades: [92,88,95] }
];

function average(grades) {
  return grades.reduce((a,b) => a+b, 0) / grades.length;
}

const results = students.map(s => {
  const avg = average(s.grades);
  return { name: s.name, avg, status: avg >= 75 ? "Passed" : "Failed" };
});

console.log(JSON.stringify(results));
› [{"name":"Juan","avg":84.33,"status":"Passed"},
   {"name":"Maria","avg":91.67,"status":"Passed"}]
