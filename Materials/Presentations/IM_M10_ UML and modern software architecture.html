Main lesson · 1

What is UML?

Unified Modeling Language (UML) is a standard visual modeling language used to specify, visualize, construct and document the artifacts of software systems, as well as for business modeling and other non-software systems.

General-purpose

A standard way to write a system’s blueprints: business processes and system functions, but also classes in a programming language, database schemas and reusable components.

A common visual language

Graphical notation for object-oriented systems lets developers communicate effectively with stakeholders such as customers and project managers.

Modern update

UML 2.5.1 and text-based modeling

The current standard is UML 2.5.1 (formalized by the OMG).

The biggest modern shift is Diagram-as-Code. Tools like Mermaid.js and PlantUML define diagrams in plain text that can be stored in Git, version-controlled and reviewed like source code. That is especially valuable for AI-assisted development, as LLMs easily generate and understand text-based diagrams.

Main lesson · 3

UML diagram classification

UML architecture uses UML diagrams to represent the structure and organization of a software system: its components, relationships and interactions.

Structural (static)

Class: classes, interfaces and relationships.
Object: a snapshot at a point in time.
Package: packages and their dependencies.
Component: the physical structure.
Deployment: deployment on hardware.
Composite structure: the internal structure of a class or object and how it is composed of other parts.

Behavioral (dynamic)

Use-case: functional requirements, use cases and actors.
State machine: states and transitions of an object.
Activity: flow of control and activities.
Sequence: interactions and message passing over time.

Modern update

The C4 model for architecture

UML is excellent for code-level design, but many modern teams use the C4 model for high-level system architecture.

A zoomable set of diagrams

C4 stands for Context, Containers, Components and Code. The diagrams are often generated as code (Structurizr DSL or C4-PlantUML), which makes them much easier to keep up to date than traditional UML diagrams.

Main lesson · 4A

PlantUML: class diagram

A class diagram models the static structure of an e-commerce system.

Class diagram (PlantUML)
@startuml
class Customer {
  -customerId: int
  -name: String
  +placeOrder(): void
}

class Order {
  -orderId: int
  -orderDate: Date
  -totalAmount: double
  +calculateTotal(): double
}

class OrderItem {
  -quantity: int
  -unitPrice: double
}

Customer "1" -- "0..*" Order : places >
Order "1" *-- "1..*" OrderItem : contains >
@enduml

What it defines

A Customer who can place many Orders, and an Order that contains many OrderItems. The *-- denotes a composition relationship.

Main lesson · 4B

PlantUML: use case diagram

A use case diagram captures functional requirements and the actors who interact with the system.

Use case diagram (PlantUML)
@startuml
left to right direction
actor "Customer" as cust
actor "Administrator" as admin

rectangle "Online Book Store" {
  usecase "Browse Books" as UC1
  usecase "Place Order" as UC2
  usecase "Track Order" as UC3
  usecase "Manage Stock" as UC4
  usecase "Check Stock" as UC5
}

cust --> UC1
cust --> UC2
cust --> UC3
admin --> UC4
UC2 .> UC5 : <<include>>
@enduml

What it defines

The <<include>> relationship shows that “Place Order” always involves “Check Stock”.

Pro tip: write the text (PlantUML or Mermaid) in a Markdown file, and your Git-based workflow renders the diagram automatically. Architecture documentation lives next to your code and is version-controlled.

Main lesson · 5

AI-assisted modeling and SysML v2

AI-assisted diagramming

LLMs can generate PlantUML or Mermaid from natural language. Prompt: “Generate a PlantUML C4 Container diagram for a web application with a React frontend, Node.js API and PostgreSQL database.” Refine the result and commit it to version control.

SysML v2

For systems engineering (hardware plus software). Recently introduced to address the complexity of cyber-physical systems with a more precise, textual notation that fits standard software workflows.

Analogy

The architectural blueprint

Use case diagram

The conversation with the client: “Do you want a garage? How many bedrooms?” It captures what the house must do.

Class diagram

The detailed blueprint of walls, doors and outlets. The static structure.

Sequence diagram

A step-by-step video of the electrician wiring a switch: first the wire goes here, then to the breaker.

C4 model

A set of maps: the city (System Context), the neighborhood (Containers), the floor plan (Components).

Real-world use case

Modernizing a legacy system

A team is rewriting a 15-year-old banking application.

  1. AI-assisted modeling parses the old COBOL code and generates PlantUML class diagrams to understand the legacy data structures.
  2. C4 diagrams map the new cloud-native architecture.
  1. Sequence diagrams design the interactions for the new mobile app’s login flow.
  2. All diagrams are stored as Mermaid or PlantUML text in the Git repository, so any developer can update and regenerate them with a commit.

Hands-on exercise

Class diagram for a simple book store

Scenario

Model a book store where an Order contains multiple Book items. Paste the PlantUML into a renderer to see the diagram.
  1. Classes: Order and Book.
  2. Attributes: e.g., orderId, title.
  3. Methods: addItem(), calculateTotal().
  4. Relationship: *-- is a composition; if the order is deleted, its items are too.
  5. Cardinality: "1" *-- "1..*" means one Order contains one or more Books.
Book store (PlantUML)
@startuml
class Order {
  -orderId: int
  -orderDate: Date
  -totalAmount: double
  +addItem(item: Book): void
  +calculateTotal(): double
}

class Book {
  -bookId: int
  -title: String
  -author: String
  -isbn: String
  -price: double
  +getDetails(): String
}

Order "1" *-- "1..*" Book : contains >
@enduml

FAQs

Common questions

How are UML diagrams classified?

Into structural diagrams (static structure, such as classes and interfaces) and behavioral diagrams (dynamic behavior, such as state transitions and interactions).

What are package diagrams for?

They represent the organization of a system into packages and their dependencies: a high-level view of how parts relate and interact.

Still draw UML manually?

You can, but the modern best practice is Diagram-as-Code: write PlantUML or Mermaid text and let a tool render it. Diagrams become version-controllable, easy to update and AI-friendly.

Aggregation vs. composition?

Aggregation is “has-a”: the part exists independently (a Department has Professors; if it closes, they still exist). Composition is “owns-a”: the part cannot exist without the whole (a House has Rooms).
