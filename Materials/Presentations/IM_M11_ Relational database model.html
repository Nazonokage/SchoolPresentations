Main lesson · 1

The relational database model

A relational database model organizes data into one or more tables (or “relations”) of rows and columns, with a unique key identifying each row. Tables are connected by relationships, defined by common columns (fields).

Logical view of data

The model represents data independently of its physical storage, in terms of entities, attributes and relations. That independence makes it more intuitive and user-friendly.

Example: a bookstore

A Books table has columns title, author, ISBN and price; each row is a book. A separate Authors table has author_name and biography. A foreign key can ensure every book has a matching entry in Authors.

Main lesson · 2

Relational integrity constraints

Rules that ensure the consistency and correctness of data in a relational DBMS. They enforce business rules and relationships between tables.

ConstraintPurpose
Primary KeyEnsures each row in a table has a unique identifier.
Foreign KeyEnsures values in a foreign key column match values in the primary key of another table.
UniqueEnsures no two rows have the same value in a specific column.
CheckEnsures values in a column meet specific conditions or criteria.
Not NullEnsures a column cannot contain a null value.
DomainEnsures values in a column are of a specific data type or range.

Main lesson · 3

Relationships in the relational model

There are three main types of relationships in a relational DBMS.

TypeDescriptionExample
One-to-One (1:1)A row in one table relates to only one row in another table, and vice versa.A User has one Profile.
One-to-Many (1:N)A row in one table relates to many rows in another table.A User can place many Orders.
Many-to-Many (M:N)Many rows relate to many rows. Resolved via a junction table.A Student enrolls in many Courses; a Course has many Students.

Main lesson · 5A

Modern evolution of relational databases

HTAP

Hybrid Transactional/Analytical Processing: supports transactional (OLTP) and analytical (OLAP) workloads in one engine, often using row and column representations at once.

NewSQL

Modern relational DBMS that offers the scalable performance of NoSQL for OLTP while keeping ACID guarantees.

Cloud-native architecture

Decoupling storage and compute enables elastic scaling, serverless operation and high availability.

AI and vector search

Databases like PostgreSQL (via pgvector) store high-dimensional embeddings for semantic search, powering AI and RAG without a separate vector database.

Main lesson · 5B

Modern SQL and multi-model databases

Modern SQL features

SQL now supports window functions, recursive queries, JSON/document support and CTEs (Common Table Expressions), breaking the traditional “relational-only” constraint.

Multi-model databases

A single kernel can natively support relational, document, vector, time-series and spatial data, reducing the need for multiple specialized databases.

Pro tip: Gartner predicts that by 2025, over 70% of new cloud-native applications will move away from traditional monolithic database architectures toward distributed data platforms.

Analogy

The filing cabinet, revisited

Relational table

A meticulously organized drawer. Each folder (row) has a unique label (primary key), and every folder has the same tabs (columns).

Foreign key

A cross-reference note inside a folder that points to a folder in a different cabinet.

Modern HTAP database

A filing cabinet that can instantly generate a pie chart of all its contents while you are still filing new documents into it.

Real-world use case

AI-powered e-commerce

The platform uses a cloud-native relational database (e.g., PostgreSQL with pgvector).

  1. Transactional data (orders, users) sits in standard tables.
  2. Product descriptions are converted into vector embeddings in a vector column.
  3. A customer searches “comfortable running shoes”. The database runs a semantic similarity search on the vectors while joining transactional data to check inventory, all in a single SQL query.

FAQs

Common questions

Advantages of the relational model?

High data integrity, flexibility in data modeling, ease of use, standardized SQL querying and wide platform support.

Disadvantages?

Difficulty with very large amounts of unstructured data, complexity in designing and maintaining the schema, challenges with complex relationships, and poor performance on unstructured data.

Primary key vs. foreign key?

A primary key uniquely identifies a row in its own table. A foreign key references the primary key of another table, establishing a relationship.

What is NewSQL?

A class of modern relational databases that combines the ACID guarantees and SQL interface of traditional RDBMS with the horizontal scalability of NoSQL.

Can relational databases store AI embeddings?

Yes. PostgreSQL (via pgvector), SQL Server and Oracle support native vector data types and similarity search.

Guided drill

Build a simple relational schema

Define a bookstore schema with tables for Authors, Books and Orders, with proper primary and foreign keys. The expected outcome is a working schema that enforces referential integrity and allows queries across related tables.

Schema (SQL)
-- Create Authors table
CREATE TABLE Authors (
    author_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    biography TEXT
);

-- Create Books table
CREATE TABLE Books (
    book_id INT PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    isbn VARCHAR(13) UNIQUE,
    price DECIMAL(10, 2) CHECK (price > 0),
    author_id INT,
    FOREIGN KEY (author_id)
        REFERENCES Authors(author_id)
);

-- Create Orders table
CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    order_date DATE NOT NULL,
    book_id INT,
    quantity INT DEFAULT 1,
    FOREIGN KEY (book_id)
        REFERENCES Books(book_id)
);
Query with JOIN (SQL)
-- Example SELECT with JOIN
SELECT Books.title, Authors.name,
       Orders.order_date
FROM Orders
JOIN Books ON Orders.book_id = Books.book_id
JOIN Authors
  ON Books.author_id = Authors.author_id
WHERE Authors.name = 'Ilse Varga';

Key definitions to remember

Relational model

Data organized into tables (relations) of rows and columns, with a unique key identifying each row.

Integrity constraints

Rules that ensure the consistency and correctness of data.

Primary key vs. foreign key

Unique identifier in its own table vs. a reference to another table’s primary key.

NewSQL

ACID guarantees and SQL, with NoSQL-style horizontal scalability.

Recap

Same core, much wider reach

The relational model organizes data into tables of rows and columns, linked by keys and governed by integrity constraints.

Its core principles are unchanged, but modern relational databases now support HTAP, cloud-native elasticity, AI vector search and multi-model data.
