Main lesson · 1

XAMPP vs. Docker

XAMPP

A popular open-source package for a local web server. It stands for Cross-Platform (X), Apache (A), MariaDB (M), PHP (P) and Perl (P). Beginner-friendly, with a control panel to start and stop services.

Its limits

Lack of isolation: one global PHP/MySQL version affects all projects.
Environment inconsistency: it runs directly on your OS, which can cause “works on my machine” issues when deploying.

Modern update

Docker for PHP development

Docker packages your entire stack (PHP, MySQL, Nginx) into isolated containers.

Consistency

The exact environment runs locally, on staging and in production.

Isolation

Run different PHP versions for different projects simultaneously.

Infrastructure as code

A docker-compose.yml file defines the setup, so the whole team can reproduce it.

Beginner recommendation: start with XAMPP to learn Apache and MySQL. Move to Docker (or tools like Local) once you collaborate or deploy production apps.

Main lesson · 2

Data Definition Language (DDL)

DDL defines and modifies the structure of database objects (tables, views, indexes). DDL statements execute immediately and cannot be rolled back.

DDL commandPurpose
CREATECreates a new database, table, or view.
ALTERModifies an existing database object (e.g., adding a column).
DROPDeletes an existing object and its data entirely.
TRUNCATERemoves all data from a table but preserves its structure.
RENAMERenames an existing database object.
CREATE INDEXCreates an index on a table to improve query performance.
CREATE VIEWCreates a virtual table based on a SELECT statement.

Main lesson · 2B

DDL code examples

DDL examples (SQL)
-- CREATE: Define a new table with constraints
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    email VARCHAR(50) UNIQUE NOT NULL,
    hire_date DATE NOT NULL
);

-- ALTER: Add a new column to the existing table
ALTER TABLE employees
ADD salary DECIMAL(10, 2) NOT NULL;

-- TRUNCATE: Empty the table but keep the structure
TRUNCATE TABLE employees;

-- DROP: Delete the table and all its data
DROP TABLE employees;

Remember

DROP removes the table definition and its data. TRUNCATE removes only the data and keeps the table structure intact.

Main lesson · 3

SQL constraints in practice

Foreign key (SQL)
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    -- FK: customer_id must exist in customers
    FOREIGN KEY (customer_id)
        REFERENCES customers(customer_id)
);

What it does

Constraints enforce rules so data stays accurate and reliable. This foreign key ensures every customer_id in orders exists in the customers table.

Main lesson · 4

Modern PHP database connection (PDO)

PHP once used mysql_* functions, removed in PHP 7.0 due to severe security vulnerabilities. Today the standard is PDO (PHP Data Objects) or MySQLi.

Why PDO?

Database agnostic: works with 12+ database systems.
Security: supports prepared statements, which prevent SQL injection.
Error handling: uses exceptions.

Security best practices

Never hardcode credentials: use getenv() or a .env file.
Set the charset: charset=utf8mb4 in the DSN.
Enable exception mode: PDO::ERRMODE_EXCEPTION.
Use prepared statements: never concatenate user input into SQL.

Main lesson · 4B

A modern PDO connection

PDO connection (PHP)
<?php
// 1. Read credentials from environment variables
$host = getenv('DB_HOST') ?: '127.0.0.1';
$db   = getenv('DB_NAME') ?: 'mydb';
$user = getenv('DB_USER') ?: 'root';
$pass = getenv('DB_PASS') ?: '';
$charset = 'utf8mb4';

// 2. Construct the Data Source Name (DSN)
$dsn = "mysql:host=$host;dbname=$db;charset=$charset";

// 3. Set PDO options (Error handling, fetch mode)
$options = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    // Use real prepared statements
    PDO::ATTR_EMULATE_PREPARES   => false,
];

try {
    // 4. Create the PDO instance
    $pdo = new PDO($dsn, $user, $pass, $options);
    echo "Connected successfully to the database!";

    // Example of a safe prepared statement
    $stmt = $pdo->prepare(
        'SELECT * FROM employees WHERE email = :email'
    );
    $stmt->execute(['email' => 'user@example.com']);
    $user = $stmt->fetch();

} catch (\PDOException $e) {
    // 5. Handle connection errors gracefully
    throw new \PDOException(
        $e->getMessage(), (int)$e->getCode()
    );
}
?>
  1. Read credentials from environment variables.
  2. Build the DSN string.
  3. Set PDO options: exception errors, fetch mode, real prepared statements.
  4. Create the PDO instance.
  5. Handle connection errors gracefully.

Analogy

Blueprint and delivery service

DDL: the blueprint and building code

Defines the rooms (CREATE TABLE), adds walls (ALTER TABLE) or demolishes the structure (DROP TABLE). Constraints are the load-bearing walls and safety rails: a NOT NULL constraint ensures no empty rooms.

PDO: the secure delivery service

mysql_* is a postcard with your bank details on the back. PDO with prepared statements is a locked armored truck: the SQL and the data stay separate, so malicious code in the data can’t affect the database.

FAQs

Common questions

DROP vs. TRUNCATE?

DROP deletes the entire table (structure and data). TRUNCATE deletes all data but keeps the structure, indexes and columns.

Can I undo a DDL command?

Most DDL commands (like DROP and TRUNCATE) are irreversible and cause immediate data loss. Back up the database before an ALTER.

Why is MySQLi less flexible than PDO?

MySQLi only works with MySQL. PDO offers one API for 12+ databases, so moving to PostgreSQL or SQLite needs no rewrite of the connection logic.

How do I handle passwords?

Never store plain text. Use password_hash() with PASSWORD_ARGON2ID or PASSWORD_DEFAULT (Bcrypt) before storing.

Hands-on exercise

Secure database setup

Create a PHP script that connects to MySQL and retrieves data safely. Assume $pdo is the connection from the earlier example.

1. Create the table (SQL)
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
3. Retrieve the user (PHP)
<?php
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);
$stmt->execute(['email' => 'student@example.com']);
$user = $stmt->fetch();

// Verify a password against the stored hash
if ($user && password_verify(
        'super_secret_password',
        $user['password_hash'])) {
    echo "Login successful!";
}
?>
2. Insert a user (PHP)
<?php
// Assume $pdo is your connection from above
$email = 'student@example.com';
$password = 'super_secret_password';

// Hash the password securely
$hash = password_hash($password, PASSWORD_ARGON2ID);

$stmt = $pdo->prepare(
    'INSERT INTO users (email, password_hash)
     VALUES (:email, :hash)'
);
$stmt->execute(['email' => $email, 'hash' => $hash]);
echo "User created successfully!";
?>
