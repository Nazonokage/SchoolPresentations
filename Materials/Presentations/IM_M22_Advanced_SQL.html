Main lesson · 1

What is a view?

A view is a virtual table based on the result of a SELECT statement. It doesn’t store data physically; the SELECT runs every time the view is queried.

Purpose

Simplify complex queries, restrict access to sensitive columns (security), and provide a consistent interface to the underlying data.

Modern update: materialized views

A materialized view physically stores the result. Common in data warehousing to pre-calculate expensive aggregations (like daily sales totals) so dashboards load instantly. They need periodic refreshing.

Main lesson · 2

What is an index?

An index is a data structure that speeds up data retrieval on a table. It works like the index at the back of a textbook: instead of reading the whole book (scanning the whole table), you find the page number (the pointer) instantly.

  • Speeds up SELECT, UPDATE and DELETE by reducing the data the engine scans.
  • Enforces uniqueness: unique indexes prevent duplicate values.
  • Facilitates JOINs: drastically speeds up joins on foreign keys.

The trade-off

Indexes speed up reads but slow down writes (INSERT, UPDATE, DELETE) because the index must be updated whenever the table changes. They also use extra disk space. Only index columns frequently used in WHERE clauses or JOIN conditions.

Main lesson · 3

Filtering results: clauses

A clause is a specific part of a SQL statement. Different clauses filter data to a manageable level.

ClausePurposeExample
WHEREFilters rows before any grouping.SELECT * FROM customers WHERE age > 25;
GROUP BYGroups rows with the same values.SELECT city, SUM(sales) FROM orders GROUP BY city;
HAVINGFilters groups after GROUP BY.... GROUP BY city HAVING COUNT(*) > 100;
LIMITRestricts returned rows (MySQL/PostgreSQL).SELECT * FROM customers LIMIT 10;
TOPRestricts returned rows (SQL Server).SELECT TOP 10 * FROM customers;
FETCH FIRSTModern SQL standard for restricting rows.SELECT * FROM customers FETCH FIRST 10 ROWS ONLY;

Main lesson · 4A

Subqueries

A subquery is a SELECT statement embedded within another SQL statement, often in the WHERE clause.

Subquery (SQL)
-- Customers who ordered in the last 30 days
SELECT name
FROM customers
WHERE id IN (
    SELECT customer_id
    FROM orders
    WHERE order_date > CURRENT_DATE - INTERVAL '30' DAY
);

Date syntax varies

CURRENT_DATE - INTERVAL '30' DAY works in PostgreSQL. SQL Server uses DATEADD(day, -30, GETDATE()).

Main lesson · 4B

Modern update: CTEs

Deeply nested subqueries become hard to read. Modern SQL developers prefer Common Table Expressions (CTEs) using the WITH clause, which make complex queries read from top to bottom.

CTE (SQL)
-- The modern way (CTE)
WITH RecentOrders AS (
    SELECT customer_id
    FROM orders
    WHERE order_date > CURRENT_DATE - INTERVAL '30' DAY
)
SELECT name
FROM customers
WHERE id IN (SELECT customer_id FROM RecentOrders);

Analogy

The library

  • Table: a massive library with millions of books.
  • Index: the card catalog. Instead of walking every aisle for “Harry Potter”, look it up and go to the exact shelf.
  • View: a curated reading list on the wall (“Top 10 Sci-Fi Books”). It creates no new books; it presents existing ones a specific way.
  • Subquery / CTE: asking the librarian, “Find the names of all authors who wrote a book published after 2020.”

Real-world use case

Dashboard performance

A company has a sales table with 50 million rows. The CEO wants a daily sales dashboard. Running SELECT SUM(amount) FROM sales on every refresh takes 10 seconds.

The solution: a materialized view that pre-calculates daily sales every midnight. The dashboard query hits the materialized view and loads in 50 milliseconds.

FAQs

Common questions

SQL vs. MySQL?

SQL is the standard query language for relational databases. MySQL is a specific RDBMS that uses SQL. SQL is the English language; MySQL is a publishing company that prints books in English.

View vs. table?

A table physically stores data on disk. A view is virtual: it stores no data and runs a saved SELECT whenever you access it.

CTE or subquery?

Use a CTE for multi-step or complex logic: it reads top-down. Subqueries are fine for simple, one-off checks.

Do too many indexes slow things down?

Yes. Every INSERT or UPDATE must also update every index on the table. With 10 indexes, a single insert becomes 11 operations. Index only columns you search by.

Hands-on exercise

E-commerce database optimization

You have a customers table and an orders table.

  1. Create an index to speed up searches by customer email.
  2. Create a view showing the total money spent by each customer.
  3. Use a CTE to find all customers who have spent more than $500.
Solutions (SQL)
-- 1. Create an index
CREATE INDEX idx_customer_email
    ON customers (email);

-- 2. Create a view
CREATE VIEW customer_total_spend AS
SELECT c.name, SUM(o.price) AS total_sales
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.name;

-- 3. Use a CTE to filter the view
WITH BigSpenders AS (
    SELECT name, total_sales
    FROM customer_total_spend
    WHERE total_sales > 500
)
SELECT * FROM BigSpenders;

Key quotes

Key definitions to remember

View

A virtual table based on the result of a SELECT statement.

Index

A data structure that improves the speed of data retrieval, at the cost of slower writes.

Subquery

A SELECT statement embedded within another SQL statement.

CTE

A WITH-clause query that makes complex logic readable from top to bottom.

Recap

Turbo-charge and tidy your queries

Views simplify logic and secure data. Indexes turbo-charge reads at the cost of slightly slower writes.

Use clauses like WHERE and HAVING to filter precisely, FETCH FIRST for modern pagination, and favor CTEs over deeply nested subqueries for readability.
