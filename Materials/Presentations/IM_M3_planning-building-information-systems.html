Main lesson · 1

The context of information systems

Information systems are designed and built to support the information needs of an organization. The context of designing and building an IS includes:

Goals and objectives

What the organization is trying to achieve.

Current information needs

What information people need right now.

Constraints or limitations

Anything that may impact the design and development of the system.

Main lesson · 2

The classic phases of system development

Modern teams often work iteratively rather than strictly linearly, but these foundational phases are critical.

PhaseDescription
Planning & Feasibility AnalysisAnalyzing the organization’s information needs, identifying potential solutions, and determining the feasibility of the proposed system.
Requirements AnalysisGathering detailed information about the system requirements, such as functional and non-functional requirements, and expected performance.
DesignCreating a detailed design for the system, including the system’s architecture, user interface, and data structure.
ImplementationBuilding and testing the system, and installing it in the organization’s environment.
MaintenanceMonitoring and maintaining the system, and making any necessary updates or improvements.

Prototyping: creating a working model of the system to test and evaluate different design options.

Main lesson · 3A

The shift to Agile and DevOps

Waterfall (historical)

A rigid, linear approach: each phase (requirements, design, implementation) is completed before the next begins.

Agile and DevOps (today)

Agile focuses on iterative delivery and adaptability. DevOps (Development + Operations) merges development and IT operations to shorten the systems development life cycle and provide continuous delivery with high software quality.

Main lesson · 3B

CI/CD, low-code and platform engineering

Continuous Integration and Continuous Deployment (CI/CD)

Instead of a single “big bang” implementation, CI/CD pipelines automate integrating code changes and deploying applications, so teams can release updates multiple times a day safely.

Low-code and platform engineering

Low-code/no-code platforms are used alongside professional development. Platform engineering treats internal infrastructure as a product, with self-service tools that let developers and business users (“makers”) build enterprise applications faster.

Main lesson · 3C

AI-native software engineering

The most significant modern shift is integrating Artificial Intelligence (AI) and Large Language Models (LLMs) into every phase of the SDLC.

AI-assisted coding

Tools like GitHub Copilot, Cursor and Claude Code act as pair programmers, autonomously planning, executing and debugging code across entire codebases.

Automated testing and documentation

AI automates test creation, bug detection and documentation generation.

Shifting developer roles

Developers move away from repetitive boilerplate toward orchestrating AI, reviewing generated code, designing system architecture and ensuring quality.

Pro tip: By 2028, Gartner predicts that 90% of enterprise software engineers will use AI code assistants, up from less than 14% in early 2024.

Main lesson · 4

Modern system architecture

The “Design” phase has moved from traditional monolithic applications (single, large codebases) to cloud-native architectures.

Microservices

Independently deployable, loosely coupled services let teams work autonomously on distinct components.

API-first design

Design the APIs before building the application to ensure modularity, reuse and interoperability with services and partners.

Event-driven architecture

Systems react to real-time events (like a user clicking “buy”), improving flexibility and performance in distributed systems.

Infrastructure as Code (IaC)

Manage and provision servers and networks through machine-readable definition files, not physical hardware configuration.

Analogy

Building an IS is like building a house

  • Planning and feasibility: can we afford it, and do we need it?
  • Requirements: how many rooms, and what must they do?
  • Design: the blueprint for structure, layout and wiring.
  • Implementation: build it, inspect it, move in.
  • Maintenance: repairs and upgrades over the years.
  • Agile: build and check one room at a time instead of everything at once.

Real-world use case

E-commerce modernization

A traditional retail company wants to build a new information system.

  1. Instead of one massive application (a monolith), it uses microservices and API-first design.
  2. It builds separate services for “Inventory,” “Payments” and “User Accounts.”
  1. With CI/CD pipelines, it updates “Payments” without taking down the whole website.
  2. Generative AI writes the API documentation and unit tests for payment processing, cutting development from months to weeks.

FAQs

Common questions

Is Waterfall completely obsolete?

Not entirely. It is still used where requirements are stable and well defined (e.g., government compliance systems). Most modern development is iterative and Agile because it handles change better.

What is “shift-left” testing?

Testing moved earlier in the SDLC. Developers write automated tests as they code, and AI tools help detect bugs during design and coding, reducing the cost and time of fixing errors later.

Do low-code platforms replace professional developers?

No. Professional developers are needed for complex integrations, security architecture and governance. In “Fusion Development,” developers build the core infrastructure and custom APIs while business users build front-end apps with low-code tools.

Recap

From rigid sequence to iterative, automated practice

Building an IS has evolved from a rigid, sequential process into a dynamic, iterative and automated discipline. Modern SDLC is characterized by Agile, DevOps, cloud-native architectures (microservices, APIs) and deep AI and LLM integration.

The developer’s role has shifted from writing code to orchestrating complex systems and ensuring quality, security and business value.
