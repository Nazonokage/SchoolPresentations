Main lesson · 1

What is a database?

A database is an organized collection of information structured so that a computer program can quickly select desired pieces of data. It is a structured set of data stored in a computer, typically used to update, query and retrieve information.

Databases manage massive amounts of data, such as customer profiles, product catalogs and financial records, and power online shopping, banking and social media.

Main lesson · 2

What is a database driver?

A database driver is a software component that enables an application to interact with a DBMS. Drivers translate the API calls made by your application into commands the DBMS understands.

  • ODBC: a standard for connecting relational databases (MySQL, SQL Server, Oracle).
  • JDBC: a Java-based API for connecting to databases.
  • ADO.NET: a data access API for the .NET framework.
  • PDO: PHP Data Objects, a data access API for PHP.
  • DB-API: a Python standard for interacting with databases.

Modern update: ORMs

Modern development relies on Object-Relational Mappers like Prisma (JavaScript/TypeScript), SQLAlchemy (Python) or Hibernate (Java). They let developers use native objects instead of raw SQL, improving security (preventing SQL injection) and speed. Drivers are still essential under the hood.

Main lesson · 3

Types of databases

There is no “one-size-fits-all” database. Engineers choose by data structure and workload.

TypeStructure, best for, examples
RelationalTables (rows and columns) linked by keys. Best for structured data, strict consistency (ACID) and complex queries, e.g., banking and ERP. Examples: MySQL, PostgreSQL, Oracle, SQL Server.
Non-Relational (NoSQL)Documents, key-value, graph or column-family. Best for unstructured or semi-structured data, massive scale and flexible schemas, e.g., social media and real-time web apps. Examples: MongoDB, Cassandra, Redis, Couchbase.
Object-OrientedData stored as objects, similar to OOP. Best for complex data structures and multimedia (images, video). Examples: Gemstone, Objectivity/DB.
HierarchicalA tree-like structure of parent-child relationships. Best for legacy systems and file systems. Examples: IBM IMS, Windows Registry.
GraphNodes (entities) and edges (relationships). Best for highly connected, relationship-heavy queries, e.g., fraud detection and recommendation engines. Examples: Neo4j, JanusGraph.

ACID stands for Atomicity, Consistency, Isolation, Durability (definition added by the deck author).

Main lesson · 4

What is database software (DBMS)?

A Database Management System (DBMS) is the program that lets you create, manage and interact with a database.

A DBMS provides

  • Data storage and organization
  • Data validation and integrity enforcement
  • Access control and security
  • A way to query and manipulate data (usually SQL for relational databases)

Modern update: Cloud DBaaS

Most organizations now use Database as a Service. Amazon (RDS, Aurora), Google (Cloud SQL, Spanner), Microsoft (Azure SQL) and Supabase manage hardware, backups and scaling, so developers focus on the data.

Guided drill

SQL vs. NoSQL data modeling

The same information stored two ways. The SQL is normalized into two tables; the document nests the posts inside the user.

Relational (SQL)
CREATE TABLE users (
  user_id INTEGER PRIMARY KEY,
  name    TEXT,
  email   TEXT
);
CREATE TABLE posts (
  post_id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(user_id),
  title   TEXT
);
INSERT INTO users
  VALUES (1, 'Odalys', 'odalys@email.com');
INSERT INTO posts VALUES (101, 1, 'My First Post');
INSERT INTO posts VALUES (102, 1, 'Second Post');
-- One JOIN to get a user and their posts
SELECT u.name, p.title
FROM users u
JOIN posts p ON p.user_id = u.user_id;
Document (NoSQL, JSON)
{
  "_id": "1",
  "name": "Odalys",
  "email": "odalys@email.com",
  "posts": [
    { "title": "My First Post",
      "date": "2023-10-01" },
    { "title": "Second Post",
      "date": "2023-10-02" }
  ]
}

The NoSQL approach needs one read to get a user and all their posts. The SQL approach needs a JOIN between two tables.

Analogy

The filing cabinet, the flexible folder and the web

Relational database

A meticulously organized filing cabinet. Everything has a specific folder (table), and labels (keys) let you cross-reference other folders.

NoSQL document database

A flexible digital folder. Throw in documents of different shapes and sizes without redesigning the folder each time.

Graph database

A web of interconnected sticky notes. Instead of looking up a note by ID, you ask, “Who is connected to what?”

Real-world use case

A modern e-commerce store

An online store like Amazon uses several database types at once.

  1. Relational (PostgreSQL): financial transactions and billing; needs strict ACID compliance because you don’t want to lose a payment.
  2. Document (MongoDB): the product catalog; Product A has 5 sizes and 3 colors, Product B is a book with an author and ISBN, so a flexible schema fits.
  1. Graph (Neo4j): powers “Customers who bought this also bought…”.
  2. Vector (Pinecone): powers the AI chatbot that semantically searches thousands of help articles.

FAQs

Common questions

What is SQL?

Structured Query Language is the standard language for relational databases, used to insert, update, query and delete data.

How is data organized in a relational database?

In tables with rows (records) and columns (attributes). Tables relate through primary and foreign keys, so data can be queried and manipulated with SQL.

How do I choose the right database type?

It depends on the amount and type of data, number of users, expected workload and consistency needs. Use relational for absolute consistency (banking); use NoSQL for massive amounts of unstructured data (social media feeds).
