Main lesson · 1

Foundations of database management systems

The foundation is the relational database: a collection of tables, each storing a specific type of data. Tables are related through keys, which link data between tables.

The purpose of database systems is to efficiently store, retrieve and manipulate large amounts of data. They serve financial systems, inventory management and customer relationship management (CRM).

Pro tip: Modern database systems are evolving into active “systems of reason” that can capture an autonomous agent’s explainable thought process to govern trust in the AI-native business era.

Main lesson · 2

Database architecture

Database architecture is the overall design and structure of a database system, including its hardware and software components.

  1. Physical layer: hardware, storage devices and network infrastructure.
  2. Logical layer: the DBMS software that manages storage, retrieval and manipulation of data.
  3. View layer: user interfaces and APIs for users and applications.

The data model defines the structure and relationships of the stored data. Some databases use a client-server architecture: the database runs on a central server and clients connect to it.

Modern update

Cloud-native and serverless architecture

Traditional

Databases tightly couple storage and compute.

Cloud-native

Databases like Amazon Aurora, Google Spanner or Databricks Lakebase decouple transactional compute from storage.

This allows serverless operation: the database can scale to zero when not in use and instantly autoscale to handle extreme bursts of traffic, such as workloads generated by AI agents.

Modern update

The rise of vector data types

In 2025, database vendors are embedding vector retrieval as a core platform capability rather than an add-on.

SQL Server 2025 includes native support for vector data types and vector search, so you can store high-dimensional embeddings alongside relational data and run similarity searches.

Main lesson · 4

Components of a database application system

These components work together to store, retrieve and manipulate data.

  1. DBMS: manages storage, retrieval and manipulation of data (MySQL, Oracle, Microsoft SQL Server).
  2. Database: where the data is stored, typically in tables.
  3. Data model: the structure and relationships of the data.
  4. Application interface: web, CLI or API access to the data.
  1. Data access layer: sits between the interface and the DBMS and translates requests into a format the DBMS understands.
  2. Query optimizer: finds the most efficient way to run a query by choosing the best indexes and reordering operations.
  3. Backup and recovery system: makes backups and restores the database after a failure.
  4. Security system: controls access, ensures integrity and encrypts data.

Modern update

AI-augmented query optimization

Traditional optimizers

Use heuristics and cost models.

Modern systems

Integrate AI for adaptive query optimization, intelligent indexing, predictive workload management and proactive monitoring.

This reduces the need for manual Database Administrator (DBA) intervention and lets the system self-tune.

Guided drill

Mapping a modern DBMS

Map the flow of a query in an AI-augmented DBMS.

  1. A user submits a natural language query (e.g., “Show me my top customers”).
  2. The LLM/GenAI layer translates it into SQL.
  3. The Query Optimizer (possibly AI-driven) plans the best execution path.
  4. The Data Access Layer fetches the data from the Decoupled Storage.
  5. The results return through the Application Interface.

Consider how a traditional DBMS would handle this request: likely a human DBA writing the SQL first.

Analogy

The smart library

  • The database: the building holding the books.
  • The DBMS: the automated librarian who knows where every book is, how to fetch it and who may read it.
  • The query optimizer: the librarian’s brain. It consults the catalog (indexes) and picks the fastest route to the shelf (execution plan).
  • A vector database: asking for “books that feel similar to this one”, found by concepts and meaning.

Real-world use case

An AI-powered e-commerce platform

An online store uses a modern cloud-native DBMS.

  1. A customer asks an AI chatbot for a recommendation.
  2. The system doesn’t just query a relational table for product_name = ‘shoes’. It uses a vector database to find shoes with similar visual embeddings or semantic descriptions.
  3. The whole operation runs on a serverless database that scales instantly for the request, then scales back to zero when idle, reducing costs.

FAQs

Common questions

What is an index?

A data structure that speeds up retrieval. It lets the DBMS locate data without scanning every row, like a book’s index helping the query optimizer.

What is the application interface?

The interface users and applications use to access and manipulate data: web interfaces, command-line interfaces and APIs for custom software.

OLTP vs. OLAP?

OLTP (Online Transaction Processing) is optimized for fast, high-volume transactions such as a sale. OLAP (Online Analytical Processing) is optimized for complex analytical queries and data warehousing. HTAP handles both.

What is a serverless database?

It scales compute up and down with demand, even to zero when idle. No capacity planning, and you pay only for what you use.

Recap

From on-premises tiers to cloud-native, AI-aware systems

A DBMS is the software layer that manages data storage and access. Architecture has evolved from rigid, three-tier on-premises systems to cloud-native, decoupled designs that separate storage and compute for extreme scalability.

AI and serverless computing are reshaping how databases are provisioned, tuned (autonomous optimization) and queried (vector and semantic search).
