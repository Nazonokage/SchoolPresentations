Core concepts

Cryptography, encryption, decryption

Cryptography
The science of secure communication techniques. Only the authorized, authenticated sender and intended receiver can view a message: masking information so only they understand it.
Encryption
Converting an original message (plaintext) into a form unreadable to unauthorized people (ciphertext). Without the tools to convert it back, it cannot be read.
Decryption
The reverse: converting ciphertext back into plaintext so it can be readily understood.
Hashing

Changing an input into a hash sum

Fixed output size
Whatever the number of input characters, the hash sum is always the same size.
One-way
A person cannot mathematically translate a hash back to the input. A computer can verify whether a guessed input matches.
Deterministic
The same input always produces exactly the same hash.

Code example

MD5 in C#

using System;
using System.Security.Cryptography;
using System.Text;

public class Program
{
    public static string CreateMD5(string input)
    {
        // Use input string to calculate MD5 hash
        using (MD5 md5 = MD5.Create())
        {
            byte[] inputBytes =
                Encoding.ASCII.GetBytes(input);
            byte[] hashBytes =
                md5.ComputeHash(inputBytes);
            // .NET 5+
            return Convert.ToHexString(hashBytes);
        }
    }

    public static void Main()
    {
        Console.WriteLine(CreateMD5("Hello World"));
    }
}
What it does
Converts the input to bytes, computes the MD5 hash and returns it as hexadecimal. Main prints the hash of Hello World.
The reality

The endless race and password strength

The “sad reality”
Hashing slows transmitted information because data must be encrypted and decrypted; with modern technology the slowdown is negligible. The bigger issue is the endless race: as technology improves, hackers exploit weaknesses in outdated algorithms like MD5 and SHA-1.
Password strength
Uppercase, lowercase, number, symbol and 8+ characters. Online MD5 “decryption” tools rely on databases of previously cracked hashes, so complex, unique passwords are not found (rainbow tables).
Analogy and use case

Lockbox, fingerprint, password storage

Lockbox and fingerprint
Encryption is a letter in a strong locked box: anyone can carry it, only the key holder opens it (decryption). Hashing is a fingerprint of the letter: you cannot rebuild the letter, but you can compare fingerprints.
Password storage
A site should never store plain-text passwords. It hashes yours (like SHA-256) and stores the hash. At login it hashes what you typed and compares. If the database is breached, hackers get hashes, not passwords.

Questions answered

Frequently asked

Why are MD5 and SHA-1 still used?
They are fast and cheap, and legacy systems rely on them. New systems should use stronger algorithms like SHA-256 or bcrypt.
Can a hash be reversed?
No. You can only guess the input and hash the guess to compare.
Encryption vs hashing?
Encryption is two-way (decrypt with a key) and used to transmit data securely. Hashing is one-way and used to verify integrity and store passwords.
Why a symbol and a number?
They enlarge the search space, defending against dictionary and brute-force attacks.

Definitions worth remembering

Recap

Key takeaways

  • Cryptography secures communication by masking information.
  • Encryption converts plaintext to ciphertext; decryption reverses it.
  • Hashing is one-way with fixed-size output.
  • MD5 and SHA-1 are outdated; AES and RSA are modern.
  • Strong passwords resist brute-force and dictionary attacks.

Answer key

Activities 1 and 2

  • 1. Apply cryptography when sending sensitive data over insecure networks like the internet, for confidentiality. Apply hashing when storing passwords or verifying file integrity, so data can be verified without storing the plaintext.
  • 2. The endless race: as encryption gets stronger, hackers gain better processing power and tools. Securing data also always adds some overhead.
  1. C: plaintext becomes ciphertext.
  2. B: MD5 gives 128 bits.
  3. C: fixed-size output.
  4. B: tools use pre-computed databases of known hashes.
