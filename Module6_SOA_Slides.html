Web Services, SOA & Microservices

How independent services find each other, speak a common language, and keep the whole system running even when one part breaks.
A · Lesson Preview

From Wiring to Architecture

In Module 5 you learned the fundamental integration methods — Point-to-Point, Vertical, Horizontal/ESB, and Common Data Format — plus jargon like Interfaces, Messages, EDI, and XML. Module 6 elevates these into real-world network architecture: Web Services, SOA, REST vs. SOAP, and Microservices.
Building modern software systems isn't about writing massive monolithic programs from scratch — it's about composing independent, specialized web services that talk to each other effortlessly across networks.

B · Main Lesson

Service-Oriented Architecture (SOA)

An architectural pattern where software applications are designed as a collection of discrete, loosely coupled, and reusable services.
01

Loose Coupling

Services remain independent; changes inside one service don't break connected systems as long as the interface stays unchanged.

02

Reusability

Services perform distinct business functions — Payment Processing, User Authentication — that multiple applications can share.

03

Interoperability

Built on open standards so different systems can exchange data effortlessly.

04

Abstraction

Internal operational logic is hidden from clients — they only interact with the published service interface.

Two Ways to Build the Same App

Monolithic Architecture

One Codebase, One Deploy

All components — UI, business logic, data access — are bundled into a single executable codebase. Simple to deploy initially, but difficult to scale, update, or maintain as team sizes expand.

Microservices Architecture

Many Small, Autonomous Services

Decomposes an application into small services organized around business capabilities. Each microservice manages its own data storage and communicates via REST APIs or message brokers.

D · Wrap-Up · FAQ

Frequently Asked Questions

Q1 — What is an API, and how does it relate to Web Services?

An API is any set of rules that lets software programs talk to each other. All Web Services are APIs, but not all APIs are Web Services — a local OS-internal API doesn't require a network.

Q2 — Why is REST preferred over SOAP for modern web & mobile apps?

REST uses lightweight formats like JSON, which need less bandwidth, parse faster in JavaScript engines, and perform better over mobile networks.

Q3 — Does Microservices replace SOA completely?

Not necessarily. Microservices can be viewed as an evolved, fine-grained implementation of SOA — focused on independent deployment, containerization (Docker, Kubernetes), and isolated data per service.
