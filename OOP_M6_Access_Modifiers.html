Menu Board

The Four Access Modifiers

Access modifiers set the visibility of classes, constructors, fields, and methods — enforcing encapsulation the way a counter, a staff room, and a back office enforce who can reach what.

🔒 private Class-level

Restricted only to the class where it's declared — like a barista's personal recipe notebook nobody else touches.

📦 default Package-level

No modifier written means visible only to classes in the same package — the house blend, shared among staff on shift.

👪 protected Package & Subclass

Accessible within the same package and by subclasses anywhere — the family recipe passed down to every franchise branch.

🌍 public World-level

Accessible from anywhere in the project, no restrictions — the menu board everyone walking in can read.

Going Further

Default (Package-Level) Access

Write no modifier at all, and Java quietly applies the "default" level — visible only to classes sharing the same package.

WarehouseDesk.java — same package

🔍 What Changes If the Package Differs?

If WarehouseDesk instead lived in a different package — say, imported from another folder — that same line would refuse to compile:

error: stockCount is not public in InventoryItem; cannot be accessed from outside package

💡 Key Takeaway

  • Default access is the quiet in-between — tighter than public, looser than private
  • Useful for helper classes that only your own package should touch
  • No keyword needed — just leave the modifier off
Going Further

Protected Access — The Franchise Recipe

protected reaches everywhere default does, plus one more place: subclasses, even if they live in a completely different package.

HouseBlendRecipe.java — parent, package A
FranchiseBranch.java — subclass, package B

💡 Key difference from default: a plain, unrelated class in com.roastery.franchise that does not extend HouseBlendRecipe still couldn't touch secretRatio — protected opens the door for subclasses specifically, not the whole outside package.

Barista FAQ

Wrap-Up & FAQs

What does public do?

It sets the accessibility level to universal — classes, fields, and methods marked public can be referenced and invoked from any other package or class across the entire project.

Why mark fields private?

Private fields protect sensitive internal data from unvalidated external modification — data encapsulation that keeps object state reliable and secure.

What's the real difference between default and protected?

Default stops at the package boundary. Protected does everything default does, plus it lets subclasses in other packages inherit access too.

Why do access specifiers matter in OOP?

They set precise boundaries for software architecture: modularity, encapsulation, fewer unintended side effects, and control over who reaches sensitive components.

Before the Skill Check

Recap

  • private, default, protected, public control visibility from tightest (own class only) to widest (entire project) — pick the tightest level that still gets the job done.
  • private is invisible outside its declaring class — expose only what's needed through public getters/setters.
  • default (no modifier) opens access to the whole package, nothing further.
  • protected adds subclasses to that reach, even across package lines.
  • public is wide open — use it deliberately, since over-exposure breaks encapsulation.
  • Encapsulating private fields behind public methods keeps object state reliable — the core habit behind every exercise today.
