Brewing Basics

What "Static" Actually Means

The static keyword makes a member belong to the class itself rather than to any one object — like an espresso machine that belongs to the shop, not to any single barista.

Single Copy

No matter how many objects are instantiated, only one copy of a static member exists in memory.

Direct Access

Static fields and methods can be called directly through the class name — no object required, e.g. ClassName.staticMethod().

Constants

Static variables are commonly paired with final to define global constants that never change.

Instance, by Contrast

Every non-static field or method belongs to a specific object — change one barista's nametag, and every other barista's stays exactly the same.

Barista Rules

Rules for Static Methods

1. Local Variables Are Fine

Static methods can freely declare and use their own local variables inside the method body — like a barista's personal notepad for a single order.

2. No Direct Access to Instance Members

Static methods cannot directly access non-static (instance) variables or methods, unless an object instance is explicitly passed in as a parameter. The shared machine can't reach into one specific barista's private locker.

The Static Counter Pattern

One of the most common real uses of static: tracking something across every object ever created, like a take-a-number ticket dispenser.

🔍 Why This Works

  • totalOrders is static — every new Order() increments the exact same shared counter

Barista FAQ

Wrap-Up & FAQs

What is a static member?

A member that belongs to the class blueprint rather than any one instance — enabling shared state and utility functions without needing object allocation.

Can a static method call an instance method directly?

No — the same rule applies to methods as to fields. It needs an object reference to call an instance method on, just like accessing an instance field.

Why is main() always static?

The JVM calls main() before any object of your class exists. Since there's no object yet, the method has to belong to the class itself.

When should I use static vs. instance?

Static for data or behavior that's the same for everyone (constants, utilities, shared counters). Instance for anything that varies from object to object.

Before the Skill Check

Recap

  • static members belong to the class, not the object — one shared copy, called directly through the class name.
  • Instance (non-static) members belong to each individual object — every object gets its own separate copy.
  • Static methods can't reach instance members directly — an object reference has to be passed in first.
  • Static methods can freely declare and use their own local variables, and can call other static methods directly.
  • The static counter pattern — a shared static field incremented inside the constructor — is a classic way to track something across every object created.
  • Pick static for shared, class-wide data; pick instance for anything that should vary per object.
