Main Lesson · Content Notes

Same OOP, New Syntax

From Java OOP applications to PHP — we're expanding your knowledge of OOP using the Java programming language as our lingua franca, our foundation for how we think about data and behavior.

Java — What You Already Know

Classes are blueprints. Objects are instances. Constructors initialize state. Inheritance builds an IS-A relationship. Polymorphism lets the same method name behave differently per object.

PHP — Same Ideas, New Accent

PHP supports the exact same OOP vocabulary — classes, constructors (__construct), extends, interfaces — but with its own punctuation: a $ before every variable, and -> instead of a dot.

We used Java as our foundation to write code in OOP style — the tone of syntax is a bit different in PHP, but it still requires that same basic OOP foundation. If any of the vocabulary here feels unfamiliar, it's worth a quick revisit to Modules 6–8 before continuing.

Setting Up Your Environment

Installing & Activating XAMPP

PHP needs a server to actually run on. XAMPP (or WAMPP on Windows, LAMPP on Linux) bundles everything you need — Apache and MySQL — in one installer.

Three Steps to "Hello, PHP"

  • 1. Download and install XAMPP / WAMPP / LAMPP for your OS
  • 2. Open the Control Panel, then Start both Apache and MySQL — wait for the status to turn green/running
  • 3. Open your browser and type localhost in the address bar to confirm the server responds

Reading the Control Panel

Two modules matter most right now:

  • Apache — the web server that actually runs your .php files, listening on ports 80 and 443
  • MySQL — the database engine, listening on port 3306, sitting there ready the moment we need it

Both show a green "Running" status once started successfully — that's your signal everything is ready.

Two Paths, Same Destination

Running PHP: Local Server vs. Online Compiler

Option A — XAMPP (Local Server)

Place your .php files inside XAMPP's htdocs folder, start Apache, then visit localhost/yourfile.php in your browser. This is exactly how real PHP applications run in production.

Option B — Jdoodle (Online Compiler)

If you want to skip installation entirely, search "PHP Jdoodle online compiler" in your browser. Paste your code, hit run, and see the output instantly — great for quick practice without a local setup.

Productivity Tip: start by writing small snippets and enhance them to make them bigger — don't try to write your whole program in one go.

Going Further

PHP Superglobals

Some predefined variables in PHP are "superglobals" — meaning they're accessible everywhere, regardless of scope, from any function, class, or file, without needing to do anything special.

$_GET

Data sent through the URL's query string, e.g. ?id=5.

$_POST

Data submitted through an HTML form using the POST method — the one you'll use most once databases enter the picture.

$_SESSION

Data that persists across multiple pages for one visitor — like staying logged in as you navigate a site.

$_SERVER

Information about the server and the current request — script paths, headers, and more.

Core Concept

What Is Polymorphism, Really?

The Greek Roots

Polymorphism is derived from the Greek words poly (meaning many) and morphism (meaning forms). Put simply: many forms.

The OOP Definition

Polymorphism is the OOP pattern that lets several classes execute or share a common interface — different classes that perform similar things use the same method name, each with its own behavior underneath.

You've actually already met this idea back in Java (Module 8, the Animal → Dog example). PHP asks exactly the same question: "if two classes do similar things, shouldn't they share a method name?"

Implementation

Two Ways to Implement Polymorphism in PHP

PHP gives you two tools for the job — the same two concepts Java uses.

Abstract Classes

Declare a method with no body inside an abstract class — every subclass must supply its own implementation.

abstract.php
Interfaces

Declare a contract of method names with interface — any class that implements it must define every method listed.

interface.php
Important Contrast

PHP Does Not Support Method Overloading

This is the single biggest syntax-tone difference between the two languages: Java lets you reuse a method name with different parameter lists. PHP simply doesn't allow it.

✅ Java — Overloading Works
Calculator.java
❌ PHP — Fatal Error
calculator.php

Overloading means creating the same method name with different data types or numbers of parameters. PHP simply refuses to redeclare a method name inside the same class — full stop. This is exactly why polymorphism (many classes, one shared method name) becomes PHP's go-to alternative for "many forms of behavior."

Guided Drill · Spot & Fix the Bug

Skill-Building Activity: Debug the Interface

Exercise 1 tests the example as-is. Exercise 2 asks you to extend it — and it has a bug hiding in plain sight.

❌ Arnold.php — won't compile

🔍 Why This Breaks

An interface is a contract — every single method it lists must appear in the implementing class, spelled exactly right. dwel() is not dwell() as far as PHP is concerned, so the contract is broken.

✅ The Fix

Rename dwel() back to dwell() — that's it. This is exactly the kind of bug real PHP developers hit constantly, and exactly why interfaces are valuable: they catch a missing method at the earliest possible moment.

The Database Was Always There

When you started your server earlier, you actually launched two things: Apache (for running PHP) and MySQL (a full relational database engine) — listening quietly on port 3306.

Making It Stick

Real-Life Analogies

Polymorphism universal remote

Press the same "power" button on a universal remote — a TV turns on, a sound bar turns on, a projector turns on. Same button, different device, different behavior.

Interface job posting

A job posting lists required duties without saying how you'll do them. Any hire (class) must be able to perform every listed duty (method) — however they choose to do it.

No Overloading one name tag per person

PHP insists each name tag (method name) inside a room (class) belongs to exactly one person — no two people sharing "Alex" even if they do different jobs.

XAMPP a starter kitchen

Apache is the stove that cooks your PHP. MySQL is the pantry, already stocked, just waiting for you to start pulling ingredients from it.

Wrap-Up

Frequently Asked Questions

Do I need XAMPP to write PHP?

No — an online compiler like Jdoodle works for quick practice. But XAMPP mirrors a real production environment, which matters once databases are involved.

Why doesn't PHP support overloading?

It's a language design choice. PHP resolves method calls more dynamically at runtime, so it simply doesn't allow redeclaring a method name — polymorphism becomes the idiomatic alternative.

What's the difference between abstract classes and interfaces here?

An abstract class can mix finished methods with unfinished ones a subclass must fill in. An interface is a pure contract — every listed method must be implemented, with no bodies at all.

Is MySQL the same as phpMyAdmin?

No — MySQL is the actual database engine. phpMyAdmin is just a friendly web interface for looking at and managing what's inside it.
