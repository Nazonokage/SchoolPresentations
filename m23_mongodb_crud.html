Quick Recap

Why MongoDB Is a Node.js Favorite

🔄 Schema-less

No rigid tables. Documents in the same collection can have completely different fields — perfect for evolving apps that need to iterate fast.

📈 Scalability

Horizontal scaling via sharding — distributes data across multiple servers for massive traffic and data loads.

🛡️ High Availability

Built-in replication — multiple copies of data across servers. If one fails, another takes over with zero downtime.

🔍 Rich Queries

Powerful filtering, sorting, indexing, aggregation pipelines, and geospatial queries — far beyond simple key lookups.

🔀 Flexible Model

Natively handles hierarchical data and nested objects that are painful to model in flat SQL tables with JOINs.

🤝 JS Integration

Data is BSON (Binary JSON) → maps directly to JavaScript objects. No ORM translation layer needed — write once, use everywhere.

Core Concept

MongoDB CRUD — The Four Methods

Every data operation maps to one of these four methods on a MongoDB collection object.

🔵 Create — insertOne(doc, cb)

Inserts a single new document (JS object) into the collection. The callback receives result.insertedId — the auto-generated ObjectId.

🟢 Read — find(filter).toArray(cb)

Queries for documents matching a filter. .toArray() converts the MongoDB cursor into a JavaScript array you can loop through.

🟡 Update — updateOne(filter, update, cb)

Modifies a single matching document. The update object uses MongoDB operators like $set to specify which fields to change.

🔴 Delete — deleteOne(filter, cb)

Removes a single document matching the filter. Check result.deletedCount to confirm the deletion actually happened.

💡 Bulk variants: Every method has a multi-document version — insertMany(), updateMany(), deleteMany(). Same syntax, but takes/affects an array of documents.
⚡ Modern alternative: These examples use callbacks (matching your lesson material). In production, developers typically use async/await with the same methods — the CRUD logic stays identical.
CRUD — Create

insertOne() — Add a Document

JS — Create (Insert)
const { MongoClient } = require('mongodb');
const url    = 'mongodb://localhost:27017';
const dbName = 'shop_db';
const client = new MongoClient(url);

client.connect((err) => {
  if (err) throw err;
  console.log('✅ Connected');

  const db         = client.db(dbName);
  const collection = db.collection('products');

  // Build the document
  const product = {
    name  : 'Wireless Keyboard',
    price : 49.99,
    stock : 120
  };

  // Insert it into the collection
  collection.insertOne(product, (err, result) => {
    if (err) throw err;
    console.log(
      '✅ Inserted ID:',
      result.insertedId
    );
    client.close();
  });
});

🔵 Create — Key Points

1

Document = JS Object

Just a plain object — keys become field names. No schema declaration needed.

2

result.insertedId

After insert, MongoDB returns the auto-generated ObjectId in result.insertedId. Use it to reference the new document immediately.

3

No CREATE TABLE

Unlike SQL, you don't declare tables or columns first. MongoDB creates the collection when you first insert into it — "lazy creation."

✅ Connected
✅ Inserted ID: ObjectId("65c1a4f3...")
CRUD — Read

find().toArray() — Query Documents

JS — Read (Query)
// Inside client.connect callback...
const collection = db.collection('products');

// READ ALL — empty filter {} returns everything
collection.find({}).toArray((err, docs) => {
  if (err) throw err;
  console.log('📋 All products:', docs);
});

// READ FILTERED — match by field value
const filter = { name: 'Wireless Keyboard' };
collection.find(filter).toArray((err, docs) => {
  if (err) throw err;
  console.log('🔍 Matched:', docs);
});

// READ WITH OPERATORS — price over 30
collection.find({
  price: { $gt: 30 }
}).toArray((err, docs) => {
  if (err) throw err;
  console.log('💰 Over $30:', docs);
});

🟢 Read — Key Points

1

find() returns a cursor

Not an array. Call .toArray() to convert the cursor into a standard JavaScript array you can loop through.

2

Empty filter = all docs

find({"{}"}) with an empty object returns every document in the collection — equivalent to SELECT * in SQL.

3

Operators use $

$gt (greater than), $lt (less than), $eq (equals), $in (in array) — all prefixed with a dollar sign.

4

No match = empty array

If no documents match the filter, docs is [] — not null. Check docs.length === 0.

CRUD — Update

updateOne() — Modify a Document

JS — Update
// Inside client.connect callback...
const collection = db.collection('products');

// UPDATE: change the price of 'Wireless Keyboard'
const filter = { name: 'Wireless Keyboard' };
const update = { $set: { price: 39.99, stock: 95 } };

collection.updateOne(filter, update, (err, result) => {
  if (err) throw err;
  console.log(
    '✏️ Matched:', result.matchedCount,
    'Modified:', result.modifiedCount
  );
});

// INCREMENT: increase stock by 50
const incUpdate = { $inc: { stock: 50 } };

collection.updateOne(filter, incUpdate, (err, result) => {
  if (err) throw err;
  console.log('📦 Stock incremented by 50');
});

🟡 Update — Key Points

1

Always use $set or an operator

Passing {"{"} price: 39.99 {"}"} without $set replaces the entire document — wiping all other fields. Always wrap changes in an operator.

2

matchedCount vs modifiedCount

matchedCount = documents that matched the filter. modifiedCount = documents that actually changed. They differ when the new value equals the old value.

3

$inc — Atomic Increment

$inc: {"{"} stock: 50 {"}"} atomically adds 50 to the current stock value. Use negative numbers to decrement. No race conditions.

✏️ Matched: 1 Modified: 1
📦 Stock incremented by 50
CRUD — Delete

deleteOne() — Remove a Document

JS — Delete
// Inside client.connect callback...
const collection = db.collection('products');

// DELETE: remove a product by name
const filter = { name: 'Wireless Keyboard' };

collection.deleteOne(filter, (err, result) => {
  if (err) throw err;

  if (result.deletedCount === 0) {
    console.log('⚠️ No matching document found.');
  } else {
    console.log(
      `🗑️ Deleted ${result.deletedCount} document(s).`
    );
  }

  // Close when all operations are done
  client.close();
});

🔴 Delete — Key Points

1

No error on zero matches

If no document matches the filter, MongoDB doesn't throw — it just returns deletedCount: 0. Always check this value to confirm the deletion.

2

Permanent removal

Unlike SQL's soft-delete patterns, deleteOne() physically removes the document. There is no recycle bin. Consider adding an isDeleted: true flag instead for production.

3

client.close() at the end

Close the connection only after ALL operations have completed. In a callback-chained script, close inside the last callback.

🗑️ Deleted 1 document(s).
Complete Script

crud.js — All Four Operations

JS — crud.js (complete)
const { MongoClient } = require('mongodb');
const url    = 'mongodb://localhost:27017';
const dbName = 'shop_db';
const client = new MongoClient(url);

client.connect((err) => {
  if (err) { console.error(err); return; }
  console.log('✅ Connected to MongoDB');
  const col = client.db(dbName).collection('products');

  // 1. CREATE
  const product = { name: 'USB-C Hub', price: 29.50, stock: 200 };
  col.insertOne(product, (err, r) => {
    if (err) throw err;
    console.log('✅ Inserted:', r.insertedId);

    // 2. READ
    col.find({ name: 'USB-C Hub' }).toArray((err, docs) => {
      if (err) throw err;
      console.log('📋 Found:', docs);

      // 3. UPDATE
      col.updateOne(
        { name: 'USB-C Hub' },
        { $set: { price: 24.99 } },
        (err, r) => {
          if (err) throw err;
          console.log('✏️ Modified:', r.modifiedCount);

          // 4. DELETE
          col.deleteOne(
            { name: 'USB-C Hub' },
            (err, r) => {
              if (err) throw err;
              console.log('🗑️ Deleted:', r.deletedCount);
              client.close();
            });
        });
    });
  });
});

🔗 Callback Chain Flow

Step 1
insertOne()
Create the document
Step 2
find().toArray()
Read it back
Step 3
updateOne()
Change the price
Step 4
deleteOne() → close()
Remove + disconnect
Callback nesting: This "pyramid of doom" works but is hard to maintain. In production, use async/await — same methods, flat code.
Real-World Analogies

MongoDB CRUD in the Real World

🗄️
The Rigid Filing Cabinet (SQL)
Every folder must have exactly the same 10 index tabs. If you add a new tab, you must reformat every single existing folder — even if most tabs are left blank. That's ALTER TABLE.
📔
The Dynamic Filing Cabinet (MongoDB)
Each folder can have whatever you want — a name, a photo, a list of songs. The next folder may have entirely different contents. No reformatting, no downtime, no migrations needed.

Real-World Use Cases

🛒 Product Catalogs

A T-shirt has size and color. A laptop has RAM and CPU. MongoDB's flexible documents store both in the same collection — no forced generic "attributes" table.

👤 User Profiles

Add "Dark Mode" or "Notification Prefs" as nested objects instantly — no ALTER TABLE on a million-row table. Documents grow organically.

📊 Real-Time Analytics

Server logs and IoT sensor data arrive at massive volume with varying structure. MongoDB's high write throughput and automatic sharding handle it effortlessly.

FAQs & Summary

❓ How do I install the MongoDB driver?

Run npm install mongodb in your project folder. This downloads the official driver that provides MongoClient and all CRUD methods.

❓ What's the connection string format?

mongodb://localhost:27017/dbName — contains the protocol, host, port (default 27017), and optionally the database name. For Atlas, the URL includes cluster and auth info.

❓ What if the filter matches nothing?

updateOne and deleteOne succeed silently with matchedCount: 0 / deletedCount: 0. No error is thrown — always check these properties.

❓ What is _id / ObjectId?

A 12-byte globally unique identifier MongoDB auto-generates as the primary key. Access it from result.insertedId after an insert.

Answer Key — Part 1

Multiple Choice Answers (Q1–7)

Q1: Command to install the driver
✅ A — npm
npm install mongodb downloads and installs the official MongoDB driver for your Node.js project.
Q2: Connection string contains address, port, and ___
✅ B — Database name
The standard format is mongodb://host:port/databaseName — specifying which database MongoClient connects to.
Q3: Class to establish the connection
✅ D — MongoClient
MongoClient is the core interface from the mongodb driver. Instantiate it with a URL and call .connect().
Q4: Event for connection dropouts
✅ C — 'error'
The 'error' event catches unexpected connection failures throughout the app lifecycle, beyond the initial connect callback.
Q5: Method to close the connection
✅ D — close()
client.close() gracefully terminates the connection, ensuring pending operations finish and resources are freed.
Q6: Method to query documents
✅ C — collection.find()
find() accepts an optional filter object and returns a cursor. Append .toArray() to convert to a JavaScript array.
Q7: Update operator for changing fields
✅ C — $set
$set specifies new values for fields without replacing the entire document. E.g. { $set: { age: 30 } } only changes the age field.
