01 · Foundations

What Is a Low-Level Language?

A low-level programming language provides little or no abstraction from a computer's instruction set — its commands map closely to the processor's own instructions. This generally means machine code or assembly language.

Why It's Fast

Low-level code talks almost directly to the machine's binary instructions, skipping the overhead an IDE or interpreter adds for higher-level languages.

Why High-Level Exists

High-level languages trade some of that raw speed for readability and developer comfort — making programming more approachable for people, not just processors.

02 · Planning Before Code

Why Flowchart First?

Flowcharting gives you a guided, visual plan of your design before a single line of code is written — a conceptual map you and others can follow and verify.

Pseudocoding

While building a flowchart, you naturally write in pseudocode — plain-English steps that a programmer or data analyst can follow without needing strict syntax.

Algorithm → (Pseudocode) = Flowcharting
03 · Core Model

The Input · Process · Output Flow

Every flowchart is built from three fundamental stages of program flow.

Input

Data enters the system — user entry, a file, a sensor reading, or another source.

Process

Validation, controls, loops, decision points, and data-bank checks act on that data.

Output

The processed result is returned — displayed, stored, printed, or sent onward.

Algorithm vs. Flowchart, in short

An algorithm is a step-by-step analysis of the process. A flowchart explains those same steps graphically. Together they clarify exactly what a program needs to do before you design something like a calculator that sends factorial results to a device.

04 · Construction

Building a Problem-Solving Flowchart

1 · Start Shape

Draw a starting terminator to state the problem or mark where the process begins.

2 · Decision Shape

Draw a diamond where you ask a question with a yes-or-no (true/false) answer.

3 · Connectors

Based on each answer, draw arrows linking the possible paths through the individual processes.

05 · Reference

Flowchart Symbols — Part I

Start / Terminator

Marks the starting or ending point of the program flow.

Data / I-O

Represents input operations (getting data) or output (displaying results).

Decision

A Yes/No or True/False question that determines the path direction.

Process

An action, operation, or computation performed on data.

Flow Line

An arrow indicating the direction of process flow between shapes.

Pre-defined Process

A sub-routine or complex process that's fully defined elsewhere.

05 · Reference

Flowchart Symbols — Part II

Connector

Links different sections of a flowchart, especially across pages.

Internal Storage

Data stored in memory or internal storage during execution.

Multi-Document

Represents multiple document outputs or reports.

Document

A printed document or hardcopy report output.

Access Storage

Direct access storage — a database or storage disk.

Manual Input

Indicates a manual data-entry step performed by an operator.

06 · From Plan to Program

Pseudocode → Working Code

The same factorial logic, first sketched as pseudocode, then implemented as real JavaScript.

PSEUDOCODE
START INPUT n SET result = 1 WHILE n > 1 result = result * n n = n - 1 ENDWHILE OUTPUT result END
JAVASCRIPT
factorial.js 
function factorial(n) {
  // iterative version of the pseudocode above
  let result = 1;
  while (n > 1) {
    result = result * n;
    n = n - 1;
  }
  return result;
}

console.log(factorial(5)); // 120
07 · Relationship

Which Comes First?

The relation between a flowchart and an algorithm is tight — algorithms dictate the steps of data flow, and flowcharts render those steps visually. Whether you're designing a calculator or an app that writes to a file, both guide the build.

It is always recommended to first write an algorithm, then draw a flowchart, and only then write the program code.

— Rule for beginners
Standard order: ALGORITHM → FLOWCHART → CODE

10 · Recap

Recap: What to Remember

Plan Before You Code

Write the algorithm first, map it with a flowchart, then implement the program — in that order.

Algorithm = Logic

A step-by-step, plain-text procedure for solving the problem, expressed as pseudocode.

Flowchart = Picture

The same logic, drawn with standard shapes — terminators, decisions, processes, and I/O — connected by flow lines.

Structure = INPUT → PROCESS → OUTPUT

Every flow, no matter how complex, is built from these three fundamental stages.

11 · FAQ

What Are the Types of Algorithms?

Simple Recursive

Solves a problem by solving smaller instances of the same problem, recursively.

Backtracking

Tests options and backtracks whenever a chosen path fails to lead to a solution.

Divide & Conquer

Breaks a problem into smaller sub-problems, solves each, then combines the results.

Dynamic Programming

Breaks a problem into simpler subproblems and stores intermediate results to avoid redundant work.

16 · Answer Key

Answers & Explanations

COMPREHENSION
Q1 — Correct: b. (int)(Math.random()+6);

Pseudocode expresses logic conceptually without full syntax. Option d is an instruction phrase, a is a direct assignment statement, and c is language-specific method syntax.

Q2 — Correct: c. Algorithm

An algorithm is the step-by-step procedure for solving a problem; a flowchart is its graphical representation.

Q3 — Correct: a. Flowchart

A flowchart uses standardized shapes — ovals, rectangles, diamonds, parallelograms — connected by arrows to show data flow.

Q4 — Correct: a. Flowchart

By definition, a flowchart gives a visual, diagrammatic breakdown of program logic.

Q5 — Correct: d. None in the list

A real process task is an actual computation or data change (e.g., x = a + b). The other options are category labels, not specific process tasks.
